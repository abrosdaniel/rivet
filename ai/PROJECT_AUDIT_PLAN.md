# Аудит проекта и план исправлений

Дата: 2026-10-07. Статус: согласованные исправления реализованы; локальная приёмка пройдена.
Ниже сохранены исходные находки аудита; номера строк относятся к состоянию до исправлений.
Релиз, изменение версии, коммит и публикация не входят в этот этап.

## Рамки и доказательства

Проверены связи 340 производственных Java-файлов, точки входа загрузчика,
конфигурация модулей, handshake, публикация/проверка/установка сборок,
основные страницы и диалоги, клиентские настройки, тестовые сценарии,
workflow и публичная документация. Проверка ссылок учитывала сервисы,
аннотации и mixin: отсутствие обычного Java-вызова само по себе не означает
мёртвый код.

В отдельном настоящем клиенте Minecraft воспроизведены:
- GUI 3: поиск «Масштаб GUI Minecraft» передаёт строку 8; после открытия
  первый видимый индекс равен 4, нужная строка 3 не видна.
- Поиск содержит «Детали оформления», которого нет в настройках.
- При tasks=false на главной отсутствует кнопка поиска по серверу.
- В широкой компоновке меню «⋯» открывает HomeWidgetsScreen, а не действия
  профиля. Входы в FollowingScreen, PlacesScreen и MapSharingScreen находятся
  только в profileActions(), доступном через компактную главную.
- Старый CommunityPlusUiHarness, начиная с шага 15, завершается ошибкой
  «Installed version missing»: ожидает кнопку, которой больше нет.

23 Python-теста tooling прошли. Проверка whitespace diff прошла.
Ранее после последних изменений прошли 305 core-тестов, build/verifyBundle
с сетевым разрешением зависимостей и сценарий сборки сервера на GUI 1/2/3.
В этом аудите полный набор UI-сценариев и GitHub CI повторно не запускался.
Успешный выход Gradle у старого harness не означает успешное завершение
его сценария: исключение перехватывается, клиент останавливается штатно.

## Подтверждённые функциональные проблемы

### A1. Поиск настроек не соответствует реальным настройкам — P1

Места:
- `rivet/mod/src/main/java/dev/abros/rivet/client/SettingsSearchScreen.java:13–24`
- `rivet/mod/src/main/java/dev/abros/rivet/client/AccessibilityScreen.java:28–43`
- `rivet/mod/src/main/java/dev/abros/rivet/client/HudSettingsScreen.java:18–24`

Индекс оформления содержит удалённую строку и умножает номер строки на два.
Виджет индексируется по постоянному списку названий, хотя строки блоков
строятся по сохранённому пользователем порядку. После перетаскивания
поиск конкретного блока также может вести не к тому пункту.

Сделать: общий источник описаний настроек и стабильные идентификаторы;
искать текущую строку по идентификатору, а не по вручную записанному числу.
Убрать отсутствующие пункты. Кнопку «Сбросить раздел» на странице поиска
заменить очисткой поиска или убрать: сейчас она только очищает запрос,
хотя подпись обещает сброс настроек (`UiSettingsShell.java:28`).

Приёмка: каждый результат действительно открывает нужную настройку на
GUI 1/2/3; результат остаётся верным после изменения порядка HUD-блоков.

### A2. Возможности главной зависят от ширины и чужого модуля — P1

Место: `CommunityScreen.java:137–148,178–188,204`.

Поиск всех разделов ошибочно скрывается вместе с задачами. Серверный
`CommunityStore` поддерживает globalSearch по другим включённым разделам
без задач. Меню профиля в широкой компоновке заменено редактором виджетов,
поэтому подписки на организаторов, общедоступные места и обмен картой
теряют вход с главной. Это проблема доступности, а не мёртвые экраны.

Сделать: независимая доступность общего поиска; одинаковый набор действий
профиля при любой ширине. Сохранить существующий диалог профиля и текущую
боковую навигацию. Редактор виджетов остаётся отдельным действием диалога.
Не добавлять новый пункт «Мой профиль» в основное меню.

Приёмка: одинаковые разрешённые действия доступны при GUI 1/2/3,
широком/узком окне и tasks=false; скрытие виджета не уничтожает входы.

### A3. Корзина показывает ложный срок восстановления — P1

Места: `CommunityScreen.java:162,261,271`; фактическое удаление —
`CommunityStore.java:225–226`, настройка `retention.trashDays`.

Список обещает 30 дней, подтверждение обещает 30 дней, карточка вычисляет
дату как deletedAt + 30 дней. Сервер может удалять записи через другой
настроенный срок. Игрок может рассчитывать на восстановление после
фактической очистки.

Сделать: передавать реальный срок/дату восстановления сервером и использовать
их во всех трёх местах. Если старый ответ не содержит срока, не обещать
конкретное число. Обновить договор ответа и проверку текстов.

Приёмка: сроки 1/30/365 дней отображаются одинаково в списке, подтверждении
и карточке; дата соответствует серверной политике.

### A4. Пресеты оформления неожиданно меняют доступность — P2

Место: `AccessibilityScreen.java:24,40`; `UiPresentationProfiles.java:5`.

Пресеты устанавливают contrast=false и opaque=false. Подтверждение говорит
о плотности, виджете, TAB и подсказках, но не предупреждает о сбросе
повышенной контрастности и прозрачности панелей.

Сделать: сохранять пользовательские параметры доступности при применении
пресета. Если изменение контрастности когда-либо станет намеренным,
согласовать это отдельно и явно описать в подтверждении.

Приёмка: выбранный высокий контраст сохраняется после каждого пресета.

### A5. Поздний ответ проверки сборки открывает закрытый экран — P2

Место: `ServerInfoScreen.java:28`.

Нажатие запускает работу в фоне без состояния занятости. Завершение всегда
вызывает setScreen, даже если пользователь уже закрыл страницу или перешёл
в другой раздел. Повторные нажатия создают несколько проверок.

Сделать: один выполняющийся запрос, индикатор занятости, привязка результата
к актуальному экрану/запросу. Уход со страницы отменяет доставку результата.
Не путать это с уже подтверждённой установкой, которую нельзя прерывать
обычным закрытием окна.

Приёмка: медленная проверка не возвращает пользователя на закрытую страницу;
повторное нажатие не ставит несколько одинаковых работ.

## Неоправданное дублирование и перегрузка меню

### U1. Сервер и Помощь повторяют один контент — P2

Места: `ServerInfoScreen.java:27–29`; `ServerMenuScreen.java:136–139`.

Описание сервера нарисовано отдельной строкой и повторно в панели
«Описание». `state.help` повторён в панели «Информация» и разделе «Помощь».

Сделать: в «Сервере» оставить описание один раз, ссылки и сведения о сборке;
текст помощи оставить в существующем разделе «Помощь». Сохранить обе
страницы и их входы. Убрать искусственное деление одного короткого текста
на две пустые колонки. Длинный текст должен переноситься и прокручиваться.

### U2. Отключённая статистика оставляет пустые/вымышленные строки — P2

Места: `ProfilePanel.java:16–18`; `CommunityScreen.java:181`.

Широкая главная показывает «Время игры —» при отсутствии totalMillis,
компактная — «Сессия: 0 с» при отсутствии sessionSeconds. Серверное
отключение статистики не должно выглядеть как нулевое время игрока.

Сделать: отличать загрузку от отключённого поля; скрывать отключённые
показатели и пересчитывать высоту/позицию действий карточки.

### U3. Статус необязательной сборки неполный — P2

Места: `ServerInfoScreen.java:28`; `ServerFeatures.java:203`.

Проверка и административный packReady ориентируются на requiredHash.
Опубликованная необязательная сборка имеет пустой requiredHash и не
получает полноценного статуса публикации/соответствия файлов.

Сделать: разделить состояния «раздача выключена», «нет публикации»,
«опубликована необязательная», «обязательная», «активные файлы проверены».
Проверять активную публикацию независимо от обязательности подключения.
Выбор компонентов сохранить в списке серверов перед входом.

### U4. Настройки уведомлений излишне плоские — предложение, P3

Место: `HudSettingsScreen.java:23–24`.

В одном длинном списке находятся общие параметры, восемь категорий и
семнадцать типов событий. «Фильтр событий» меняет область настройки,
но связь фильтра с последующими переключателями неочевидна.

Предложение: визуальные группы и раскрываемый подробный блок в том же
диалоге, подпись текущей области действия. Не добавлять новые страницы.
Сначала исправить A1, чтобы группировка не сломала поиск ещё раз.

### U5. Действия игрока повторены намеренно — не удалять автоматически

`FeatureListScreen` содержит быстрые «Написать», «Пожаловаться»,
«Пригласить», а `PlayerActionsScreen` — те же действия в полном профиле.
Это допустимые контекстные сокращения пути. Не удалять их ради отсутствия
повторов. Если понадобится уменьшить карточку, согласовать конкретный
набор; источник доступности/прав и названий должен быть общий.

## Мёртвый/неэффективный код

### D1. Старый рендерер иконок серверов — P2

`Branding.java:6–14`: `serverIcon`, record Texture и LRU-кэш не имеют
вызовов в production, harness или ресурсах. Обычный список серверов
рисует свои иконки сам. Удалить этот блок, сохранить `Branding.icon` Rivet.

### D2. Неиспользуемый алиас проверки версии — P2

`Versions.java:28–29`: `supportsBranch` больше никто не вызывает.
Публичного стабильного API для сторонних модов пока нет. Удалить алиас;
сохранить действующий supportsRequirement и проверки handshake.

### D3. Остатки прежних настроек загрузки — P2

`Remote.java:36–39`; `DownloadSettings.java`; `Cache.java:105`.

configureDownloads не вызывается. Поле parallel вообще не читается.
Предел скорости всегда 0, зеркало всегда auto, поскольку экран настроек
загрузки удалён. Ветви ограничения скорости и выбора предпочитаемого
зеркала фактически недостижимы в продукте.

Сделать: удалить неиспользуемый конфигуратор и связанные неэффективные
параметры/ветви, сохранив реальную загрузку, retry, отмену, resume и cache.
Не добавлять новый пользовательский экран для оправдания старого кода.

### D4. Неэффективный параметр детализации оформления — P2

`AccessibilityScreen.java:10–15,24,51`: decoration загружается,
сохраняется, изменяется пресетом, но decoration() нигде не используется.
Двухаргументный конструктор AccessibilityScreen игнорирует section и
тоже не имеет вызовов. Убрать неэффективное состояние и конструктор,
сохранить действующие density/motion/contrast и данные других настроек.

### Что НЕ считать мёртвым

RivetLocator зарегистрирован через ServiceLoader; mixin и callback-методы
используются загрузчиком/фреймворком. trackedReads, Rect.overlaps и
Remote.awaitSource имеют тестовые/диагностические потребители.
Не удалять их по одному только отсутствию production-вызова.
GitHub нужен обновлению самого Rivet, а не прежней системе сборок:
CoreUpdater остаётся действующим кодом.

## Проверки и документация

### T1. Устаревшие локальные UI-сценарии — P2

`CommunityPlusUiHarness.java:35,42` ожидает старую кнопку установленной
версии и UiToggle прозрачности; текущие экраны используют другие элементы.
Первую ошибку воспроизвели. `CommunityUiHarness` также содержит старые
поиски элементов («Поведение» и др.).

Эти сценарии не включены в текущий ci.yml; найденная ошибка не является
доказательством падения нынешнего CI. Но ими нельзя подтверждать качество
интерфейса. Старые harness напрямую делают Screenshot.grab, обходя общий
RIVET_UI_SCREENSHOTS=false; некоторые ошибки не дают FAILED-маркер.

Сделать: сопоставить старые сценарии с действующими, сохранить уникальную
проверку поведения, удалить дублирующие/устаревшие части; общий UiCaptureHarness
и обязательные OK/FAILED-маркеры. Добавить проверки A1–A8, включая реальные
клики, модульные выключатели, разные размеры и доступность действий.
Не увеличивать матрицу всеми сочетаниями всех тем.

### T2. Документация модулей отстала — P2

`docs/development/modules.md:27` утверждает, что core не импортирует
NeoForge. После JarJar-аудита используются loader-independent
net.neoforged.jarjar библиотеки. Уточнить границу: нет Minecraft/game API
и клиентских экранов, допустима библиотека разбора/выбора JarJar.
Не ослаблять существующий build guard для прочих импортов NeoForge.

## Дополнительные находки расширенного прохода

Проверка расширена на исходные переводы, устаревшие новости/правила,
вспомогательные методы, демонстрационные экраны, состав готового game-module
JAR и локальные ссылки публичной документации. Игнорируемые build/run-копии
не считаются действующими исходниками. В отслеживаемых публичных Markdown
не обнаружены сломанные относительные ссылки на локальные файлы.

### A6. Проверка изменений сборки теряет прокрутку — P1

`ReviewScreen.java:10` вызывает `super.init()`, затем `clearWidgets()`.
`ScrollScreen.java:9` при очистке сбрасывает layout, созданный TextScreen.
Поэтому исчезает полоса прокрутки, а колёсико над текстом не обрабатывается.
Это мешает прочитать большой список файлов до подтверждения установки.

Подтверждено в отдельном настоящем клиенте, GUI 3, текст из 100 строк:
layout=false, wheelHandled=false, firstRow остаётся 0, visibleRows=21.
Успешный выход Gradle здесь не заменяет проверку: проверены именно значения
области прокрутки и результат события колёсика.

Сделать: общий способ заменить нижние действия TextScreen без удаления
области чтения; ширины кнопок вычислять внутри диалога. Проверить перенос
по ширине содержимого, включая отдельный отступ полосы прокрутки.

Приёмка: длинный список читается колесом, клавиатурой и перетаскиванием
полосы на GUI 1/2/3; смена размера не сбрасывает доступность текста;
кнопки установки/отмены не выходят из границ диалога.

### A7. Отправка обращения расходится с обещанным сценарием — P2

`ReportScreen.java:35–49`: «Отправить» собирает данные и сразу посылает
запрос. Предварительного просмотра и отдельного подтверждения нет.
`rivet.server.helptext` в ru_ru/en_us обещает отправку только после просмотра
и подтверждения. Старые preview/reportprivacy-переводы не используются.

Сделать: согласовать форму с обещанным сценарием — существующий диалог
предпросмотра текста и передаваемых сведений, затем явная отправка.
Не возвращать удалённый экспорт журналов Diagnostics ради этой задачи.
Сохранить черновики, безопасный повтор и идемпотентность.

Приёмка: до подтверждения сервер не получает обращение; отмена сохраняет
черновик; повтор не создаёт второе обращение. Показанные сведения совпадают
с реальными message/category/coreVersion/packHash/audit.

### A8. Локализация общих действий обходится — P2

`UiActions.java:11–16`: enum хранит ключ label, но поле никто не читает.
Общие «Назад», «Закрыть», «Повторить», «Обновить» строятся русским literal,
поэтому английские переводы этих действий не используются. Это не повод
удалять переводы: общий компонент должен применять правильный ключ.

Сделать: использовать label для Client.tr; проверить общие действия и
подсказки в RU/EN. Отдельно составить список оставшихся русских литералов
пользовательских экранов и переводить согласованные пользовательские тексты,
не затрагивая серверный контент и имена игроков.

Обычные тексты о правилах поведения и SQL-история не являются остатками

### D6. Невостребованный экспорт диагностики — P2

Не удалять действующую серверную диагностику, Spark/VoiceDiagnostics,
