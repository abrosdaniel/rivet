# Управление сервером

Объявления, обслуживание и остановка через API.

`GET /api/v1/admin/server` возвращает сохранённое целевое состояние и его
`revision`. Нужны `server.control.read`, сессия игрока и хотя бы одно право
`rivet.restart`, `rivet.maintenance`, `rivet.announce`. WebSocket использует тот же ресурс.

Команды требуют `server.control.write`, сессию и соответствующее актуальное
право игрока. Онлайн присутствие сотрудника не требуется. В `If-Match` передаётся
заключённая в кавычки ревизия из GET. В теле — обычные `operationId`, `issuedAt`, `data`.

| POST после `/api/v1/admin/server/` | Поля `data` | Право |
| --- | --- | --- |
| `restart` | `seconds` (0–86400), `reason` | `rivet.restart` |
| `maintenance` | `enabled`, `minutes` (0–10080), `reason` | `rivet.maintenance` |
| `announcement` | `text`, `minutes` (1–10080) | `rivet.announce` |

`seconds: 0` отменяет остановку. После отсчёта сервер сохраняет мир и завершает
процесс; повторный запуск выполняет панель или внешний supervisor. `minutes: 0`
для техработ означает отсутствие срока. Пустой текст снимает закреплённое объявление.
Ответ подтверждает сохранение целевого состояния; сервер применяет его в своём
потоке через ограниченную очередь. При занятости обработчика применение повторяется.
При запуске сервера прежняя запланированная остановка сбрасывается, техработы
восстанавливаются по существующим правилам. API не выполняет произвольные команды.

Повтор исходного запроса возвращает прежнюю квитанцию и не переносит время остановки.
Отозванное право блокирует также повтор. Конфликт ревизии возвращает 409. Ключи
по-прежнему создаются и изменяются только в локальной серверной консоли.
