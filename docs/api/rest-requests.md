# Запросы и ошибки

Формат запросов, повтор изменений, курсоры и обработка ошибок.

Базовый путь — `/api/v1`. JSON UTF-8, Content-Type `application/json` для тел
POST/PUT. Лимит тела HTTP — 16384 байта. GET, DELETE и OPTIONS не принимают тело;
Transfer-Encoding и дубли одиночных заголовков отклоняются. Неизвестные поля,
параметры и повторяющиеся JSON-ключи не игнорируются. Процентное кодирование
в request target не поддерживается; передавайте только предусмотренные контрактом
идентификаторы и параметры.

Операции изменения используют явные маршруты и типизированные тела из OpenAPI.
Сохраняйте ID операции при повторе запроса; ревизии и If-Match защищают от потери
чужих изменений. Таймаут не доказывает, что запись не состоялась. Ключи, пароли
и произвольные игровые команды не передаются в доменные команды.

Ответ ошибки содержит `error.code`; текст не является стабильным контрактом.
Основные статусы: 400 — неверный запрос, 401 — нет действующей авторизации,
403 — нет права, 404 — объект отсутствует или скрыт, 409 — конфликт,
429 — ограничение нагрузки, 503 — сервис или модуль недоступен.
При `RESYNC_REQUIRED` получите новый снимок и cursor. Cursor принадлежит
конкретному потоку; он не предоставляет доступ к данным.

Списки возвращают nextCursor; сохраняйте snapshot там, где он указан в схеме.
ETag/304 применяется только к поддерживающим это ресурсам и только после проверки
доступа. Ответы с личными данными нельзя помещать в общий кэш.
