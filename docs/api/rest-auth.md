# Авторизация запросов

Ключ приложения, сессия игрока и проверка прав.

Ключами управляет только серверная консоль. Передавайте постоянный ключ в
`Authorization: Bearer <key>`; scope проверяется отдельно для каждой операции.
Ключ нельзя помещать в URL или браузер. Разрешённый Origin не разрешает браузеру
использовать постоянный ключ: CORS обслуживает только явно открытые публичные ресурсы.
Не журналируйте Authorization, X-Rivet-Session и пароли.

Для личных данных дополнительно требуется `X-Rivet-Session`. При включённом Auth
доверенное приложение с `sessions.password` получает сессию через
`POST /api/v1/sessions/password` с полями `login` и `password`.
При выключенном Auth используется `sessions.link`: запрос
`POST /api/v1/sessions/link`, подтверждение кода игроком и обмен через
`POST /api/v1/sessions/exchange`. Точные тела и ответы перечислены в OpenAPI.
Сессия привязана к выдавшему её ключу; отзыв, истечение, блокировка учётной записи
и смена поколения авторизации прекращают доступ. Сессии не переживают перезапуск.

Права ключа не заменяют права игрока: членство, приватность, серверные разрешения
и включённость модуля проверяются доменным сервисом. Административные действия
поддерживают офлайн-пользователей с актуальной проверкой серверных прав.
Позиции и Waystones доступны только от имени онлайн-игрока с разрешённым доступом.
