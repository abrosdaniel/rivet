# Статус и курсоры

Чтение снимков и восстановление после пропущенных событий.

`serverStatus()` возвращает число игроков, максимальный онлайн, состояние
обслуживания, время запланированного завершения в миллисекундах Unix и capabilities.
Причина остановки, имена, UUID, координаты, профили и конфигурация не выдаются.
При отключённом управлении сервером maintenance=false и shutdownAtEpochMillis=0.

Доступны `server.status`, `server.status.events` и фасад `domains` с `domains.watch`. Наличие игрового модуля
само по себе не означает, что его API реализован. Клиент обязан проверять
capabilities, а не угадывать доступность по номеру версии Rivet.

Снимки обновляются на серверном потоке после тика. Чтение статуса потокобезопасно:
оно получает готовые неизменяемые DTO, не обращаясь к миру или базе данных.

## Курсоры и восстановление

Снимок и cursor получаются атомарно. `serverStatusEvents(cursor, limit)` читает
изменения строго после cursor, в порядке sequence. Limit — от 1 до 256.
История хранит последние 256 изменений; одинаковое состояние не создаёт событие.
`hasMore=true` означает, что нужно продолжить с возвращённого nextCursor.
Пустой результат не продвигает cursor.

При устаревшем cursor, cursor от другого запуска или sequence из будущего
возникает `ApiException` с кодом `RESYNC_REQUIRED`. Получите новый снимок
и продолжайте с его cursor. Это временная история в памяти, не журнал в базе.

После остановки сервера сохранённый интерфейс возвращает `UNAVAILABLE`,
а discovery больше не возвращает завершившийся runtime. Ошибки обрабатываются
по `ApiException.code()`, текст сообщения не является стабильным контрактом.
