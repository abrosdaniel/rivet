# Работа с данными

Асинхронные доменные операции и контекст игрока.

`api.publicDomains()` создаёт контекст публичного чтения. `api.domains(playerUuid)`
создаёт контекст конкретного игрока для доверенного установленного мода. UUID
не является доказательством авторизации: сторонний мод сам связывает его с
аутентифицированным игроком. Не принимайте UUID из внешнего запроса без проверки.
Привилегированные операции отдельно проверяют актуальные серверные права; UUID сам по себе их не предоставляет. Контекст может
читать данные известного офлайн-игрока; имя берётся из Rivet, а не от потребителя.

Контракты — `DomainApi`, неизменяемые `DomainData` и закрытый набор `DomainCommand`.
Они не содержат Gson, Minecraft, внутренних меню или SQL. Списки защищены от
изменения. Время — миллисекунды Unix, ноль означает отсутствие; цвет — непрозрачный
ARGB. Отсутствующие/недоступные поля представлены `Optional` или пустой строкой.

| Метод | Данные |
| --- | --- |
| `capabilities()` | Доступные `groups.read`, `groups.write` и другие операции текущего контекста |
| `community`, `document` | Объединения (`Community.GROUPS`) |
| `profile` | Профиль по действующим настройкам приватности |
| `notifications` | Свои уведомления, без автоматической отметки прочитанными |
| `chat`, `channels` | Разрешённая история и доступные каналы |
| `publications`, `publication` | Опубликованные объекты карты либо собственные черновики (`own=true`) |
| `territories` | Видимые территории объединений |
| `execute` | Типизированная команда от имени игрока |

Пустой cursor начинает список; следующие страницы используют `nextCursor`.
Для публикаций дополнительно сохраняйте `snapshot` первой страницы; при `CONFLICT`
начните чтение заново. Размеры страниц и фильтрация совпадают с REST. Исследованная
местность клиента через эти сервисы не передаётся.

```java
RivetApi.connect("example_mod").ifPresent(api -> {
    DomainApi view = api.domains(playerUuid);
    view.community(DomainData.Community.GROUPS, "")
        .thenAcceptAsync(page -> {
            // Неизменяемые DTO; для обращения к Minecraft перейдите на server.execute(...).
            for (var group : page.items()) consume(group.id(), group.title());
        }, consumerExecutor);
});
```

Доступны создание и управление объединением, сохранение своего профиля,
отметка уведомления прочитанным, подача, изменение и отзыв публикации карты,
обращения, модерация и отправка чата. Проверяются права текущего игрока.

Типы удалённых механик сохранены для совместимости загрузки сторонних модов.
Операции задач, событий, доски, опросов и предложений возвращают `UNAVAILABLE`;
они не появляются в `capabilities()`. Проверяйте возможности перед показом действий.
Сохранённые данные экспортирует владелец сервера через архивный инструмент.

```java
var operationId = java.util.UUID.randomUUID();
long issuedAt = System.currentTimeMillis();
var command = new DomainCommand.CreateGroup("Строители", "Совместные постройки", "Команда");
view.execute(operationId, issuedAt, command).thenAcceptAsync(receipt -> {
    // Сохранить receipt.id() и receipt.revision().
}, consumerExecutor);
```

Изменение существующих данных требует актуальной ревизии. Повтор после сетевой
или временной неопределённости использует те же `operationId`, `issuedAt` и команду:
квитанция гарантирует отсутствие повторной записи в пределах окна 24 часа.
Квитанции разделены по mod ID и игроку; они не пересекаются с REST-приложениями.
Публичный контекст не исполняет команды. Проверки владения, членства, выключенных
модулей и правил публикации выполняются при каждом обращении к существующим сервисам.

## Потоки, нагрузка и остановка

Доменные методы возвращают `CompletableFuture`. Они не выполняют DB/сетевую работу
на вызывающем потоке. Не используйте `join()`/`get()` на игровом тике. Результат
завершается на API-worker; обработчики с вычислениями, ожиданием или пользовательским
кодом запускайте через `thenAcceptAsync`/`handleAsync` со своим executor.

Один сервер обслуживает два API-worker и очередь до 64 операций. При заполнении
возвращается `ApiException(BUSY)`. Неиспользуемые worker завершаются через 30 секунд;
они не запускаются до первого запроса. Дедлайн результата — 10 секунд
(`TimeoutException`). Отмена/таймаут до начала исполнения пропускает операцию.
Отмена уже начавшейся записи не гарантирует rollback: повторяйте её с прежним ID.
SQL дополнительно ограничен таймаутами базы данных.

При остановке pending futures завершаются `UNAVAILABLE`, очередь отменяется,
worker прерываются с ограниченным ожиданием. Сохранённые контексты закрытого сервера
не переходят в новый запуск. Прочие ошибки обрабатывайте по `ApiException.code()`
в причине завершения future. Подписки на изменения описаны ниже; сетевые push-снимки — в [WebSocket API](websocket.md).

## Уведомления от своего мода

`api.notifications()` создаёт владельца типов уведомлений в пространстве ID
подключённого мода. Сохраните его до отключения адаптера. Записи доставляются по
UUID, в том числе офлайн-игрокам; они доступны в обычном списке уведомлений,
через `DomainApi.notifications` и подписку `DomainWatch.Notifications`.

```java
var notifications = api.notifications();
var deliveries = notifications.register("deliveries");
var message = new NotificationsApi.Message("Посылка готова", "Заберите её на почте.");

deliveries.put(playerUuid, "package-42", message, 0)
    .thenAcceptAsync(receipt -> saveReceipt(receipt), consumerExecutor);

// При отключении адаптера, а не сразу после запуска асинхронной операции:
// notifications.close();
```

Ключ записи уникален в пределах типа и получателя. Повторная отправка с ревизией
`0` и тем же текстом возвращает существующую квитанцию без нового уведомления.
Другой текст требует актуальную `receipt.revision()`; устаревшая ревизия даёт
`CONFLICT`. Ревизии непрозрачны: сохраняйте полученное значение, не вычисляйте его.
Обновление сохраняет ID, время создания и отметку «прочитано».

`deliveries.revoke(playerUuid, "package-42", receipt.revision())` удаляет свою
запись. Чужой тип или получатель не затрагиваются. Уже отсутствующая запись —
успешный повторный вызов. После удаления и создания заново старая ревизия
не подходит новой записи.

Хранятся последние 200 уведомлений игрока; защита от повторной отправки действует,
пока запись сохранена. Закрытие регистрации или остановка API не удаляют историю.
Уже выполняющаяся операция может завершиться; ожидающие операции закрытого типа
получат `UNAVAILABLE`. После запуска сервера зарегистрируйте типы заново.

ID типа и ключ: 1–64 латинские буквы, цифры, `_`, `.` и `-`; первый символ —
буква, цифра или `_`. До 16 типов на мод и 256 на сервер. Заголовок ограничен
300 символами, текст — 1000. Текст отображается буквально: без команд, ссылок
с действиями и разметки. API использует ограниченную очередь; при переполнении
возвращает `BUSY`. Не вызывайте `join()` на игровом потоке. Этот издатель доступен
только доверенным установленным Java-модам, без расширения прав REST-ключей.

### Язык уведомления

Передайте до восьми переводов вместе с запасным текстом. Переводы сохраняются с
уведомлением и не требуют установки вашего мода на клиенте:

```java
var message = new NotificationsApi.Message(
    "Parcel ready", "Collect it at the post office.",
    java.util.Map.of("ru_ru", new NotificationsApi.Translation(
        "Посылка готова", "Заберите её на почте.")));
```

Идентификатор языка — `ru_ru`, `en_us` и аналогичные: 2–3 строчные латинские буквы,
подчёркивание и две буквы региона. На каждый перевод действуют те же ограничения
длины, что на запасной текст. Совпадение языка точное; при отсутствии перевода
показывается запасной текст. Перевод не интерпретируется как ключ или разметка.
Изменение только перевода тоже требует актуальной ревизии уведомления.

В игре язык выбирается по настройкам получателя. Клиент получает выбранный текст,
а не полный словарь переводов. Для Java-чтения используйте
`view.notifications(cursor, "ru_ru")`; вызов без языка возвращает запасной текст.
Для REST — `GET /api/v1/me/notifications?locale=ru_ru`. Права и сессия игрока
проверяются так же, как при чтении без `locale`.

### Срок действия

Четвёртый аргумент `Message` задаёт `expiresAt` — абсолютное время Unix в
миллисекундах. Например, уведомление, актуальное десять минут:

```java
var message = new NotificationsApi.Message(
    "Посылка ожидает выдачи", "Заберите её до закрытия почты.",
    java.util.Map.of(), System.currentTimeMillis() + 10 * 60_000L);
```

`0` означает отсутствие срока действия; прежние конструкторы используют `0`.
Ненулевой срок должен быть в будущем. Повторная отправка сохраняет тот же
`expiresAt`: если каждый раз вычислять новое время, потребуется текущая ревизия.

После истечения запись исключается из списка, счётчика непрочитанного, HUD и API.
Ожидающие и отложенные HUD-уведомления также истекают. Истечение не отмечает запись
прочитанной. Фоновая очистка удаляет просроченные записи небольшими порциями и
уведомляет подписчиков об изменениях. Старые уведомления без срока действия
сохраняют обычный лимит истории — 200 записей на игрока.

После истечения ключ можно использовать для нового уведомления с ревизией `0`.
Старая ревизия не позволяет изменить или удалить эту новую запись. Фактическое
удаление из базы может произойти позже, но выдача через API уже исключает запись.

### Переход из уведомления

`OpenGroup` добавляет кнопку открытия карточки объединения:

```java
var message = new NotificationsApi.Message(
    "Новости объединения", "Откройте карточку, чтобы узнать подробности.",
    java.util.Map.of(), 0, new NotificationsApi.OpenGroup(groupUuid));
```

`OpenReport(reportUuid)` открывает собственное обращение получателя. Уведомление
не даёт доступа к чужому обращению или административной очереди.

`OpenOwnPublication(publicationUuid)` открывает собственную публикацию карты
получателя. Чужие черновики недоступны; переход не одобряет и не публикует объект.

Это переход в игровом меню. Он не вступает в объединение и не выполняет команду.
Сервер при нажатии проверяет получателя, срок действия и ревизию уведомления,
доступность модуля и самой карточки. Изменение или удаление действия требует
актуальной ревизии. Клиент не может заменить сохранённый адрес перехода.

Внешние приложения по-прежнему читают текст через `DomainApi` и REST; этот
игровой переход не предоставляет дополнительных прав API-ключу. Произвольные
команды, URL и обработчики клика через `Message` не принимаются.

Список уведомлений и HUD открывают актуальную запись с сервера. Старые уведомления
используют тот же путь: их текст остаётся доступен, а переход к удалённой или
недоступной записи отклоняется.

### Подписки на уведомления и настройки

```java
var inbox = domains.watch(new DomainWatch.Notifications("ru_ru"));
var preferences = domains.watch(new DomainWatch.NotificationPreferences());
```

Подписка на входящие возвращает первую страницу и обновляет её после изменения
или отзыва уведомлений. Без аргумента `new DomainWatch.Notifications()` использует
сохранённый текст по умолчанию. Если перевода нет, возвращается тот же текст.
Язык фиксируется на время подписки; для смены языка закройте её и создайте новую.
Подписка на настройки возвращает категории без уведомлений и срок паузы.

Обе подписки используют обычный `DomainSubscription`: забирайте события через
`poll()` и закрывайте дескрипторы, когда они больше не нужны. Повторная подписка
получает свежий снимок с новым потоком. При ошибке проверяйте событие `Closed`;
закрытая подписка автоматически не возобновляется.

Категория стороннего уведомления — ID типа `mod:type`. Игрок может отдельно
отключить всплывающие сообщения этого источника. Это сохраняет его входящие
и счётчик непрочитанных. Старое общее отключение категории `notifications`
продолжает действовать для всех сторонних источников.
