# Подписки Java

Получение изменений без периодического опроса.

`DomainApi.watch(DomainWatch<T>)` возвращает закрываемый `DomainSubscription<T>`.
Возможность поддерживается, если в статусе есть `domains.watch`; конкретные домены
также сообщают `tasks.watch`, `notifications.watch` и другие capabilities.

Селекторы `DomainWatch`: `CommunityList`, `CommunityDocument`, `Tasks`, `Task`,
`Profile`, `Notifications`, `Chat`, `Channels`, `Publications`, `Publication`,
`Territories`. Они используют тот же контекст и проверки прав, что обычные чтения.
Нельзя подписать публичный контекст на личные уведомления или собственные черновики.

```java
import dev.abros.rivet.api.*;
import dev.abros.rivet.api.DomainData.*;

// Сохранить handle на время работы интеграции, а не создавать каждый тик.
DomainSubscription<Page<Notice>> subscription =
    view.watch(new DomainWatch.Notifications());

// В тике потребителя: poll() не выполняет IO и не ждёт чтения БД.
subscription.poll().ifPresent(event -> {
    if (event instanceof DomainSubscription.Snapshot<Page<Notice>> snapshot) {
        replaceNotices(snapshot.value().items());
    } else if (event instanceof DomainSubscription.Closed<Page<Notice>> closed) {
        clearNotices();
        closed.error().ifPresent(code -> handleSubscriptionError(code));
    }
});

// При выключении интеграции/уходе игрока:
subscription.close();
```

Rivet не вызывает обработчики стороннего мода: `poll()` передаёт готовый DTO, а код
потребителя исполняется только там, где сам потребитель его вызвал. Медленный или
ошибающийся обработчик не занимает worker Rivet. Один handle предполагает одного
потребителя; параллельные `poll()` безопасны, но разделяют сообщения между вызовами.

Первое сообщение — полный `Snapshot<T>`. Затем выдаётся новый снимок только при
изменении данных. Сигналы коммита проверяются раз в секунду, дополнительная проверка
раз в пять секунд учитывает срок хранения и изменения без сигнала. Это интервалы
планирования; длительность очереди и чтения БД может увеличить задержку.
Права и включённость модуля проверяются при каждом обновлении.

У подписки один слот: более новый снимок заменяет непрочитанный. `ApiCursor.stream`
уникален для handle, `sequence` увеличивается при наблюдённом изменении; пропуски
номеров означают объединённые состояния. Это снимки текущего состояния, не журнал
каждой операции. Списки наблюдают первую страницу; изменения исключительно на других
страницах не обязаны создавать событие. Остальные страницы и пропущенные сообщения
чата догружаются обычными методами `DomainApi` с `nextCursor` и правилами хранения.

`poll()` возвращает событие один раз, затем `Optional.empty()`, пока нет нового.
`Closed<T>` заменяет ожидающий снимок и удаляет сохранённые в подписке данные.
При отзыве доступа, удалении объекта или выключении модуля содержит код
`ApiException`; при остановке сервера — `UNAVAILABLE`, при ручном `close()` ошибка
отсутствует. `isClosed()` остаётся `true` и после получения terminal event.
Получив `Closed`, потребитель должен удалить свои копии приватных данных.

Максимум восемь подписок на mod ID (включая все его контексты игроков) и 64 на сервер.
Превышение возвращает `BUSY` при создании. Используется существующая очередь доменных
чтений; одна подписка не запускает два чтения одновременно. Ошибка/переполнение этой
очереди закрывает соответствующую подписку с кодом ошибки. При необходимости создайте
новую после задержки. Каждая новая подписка начинает с актуального снимка, cursor
старой подписки не воспроизводится. Не требуется отдельная очередь callback-ов.

`close()` идемпотентен, отменяет ожидающее чтение и подавляет поздний результат уже
начатого чтения. Таймер создаётся только при первой подписке и завершается после
закрытия последней. Остановка API закрывает все handles; после нового запуска нужно
заново подключиться и подписаться.
