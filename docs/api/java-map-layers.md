# Собственные слои карты

Добавьте метки и территории своего мода.

`api.mapLayers()` выдаёт отдельный handle владельца для ID подключённого мода.
Слой получает имя `mod_id:local_id`; изменение объектов возможно только через
handle этого слоя. Повторная регистрация занятого имени возвращает `CONFLICT`.

```java
var owner = api.mapLayers(); // сохранить до отключения интеграции
var layer = owner.register(new MapLayersApi.LayerSpec(
    "stations", "Станции", MapLayersApi.Audience.publicAccess()));
long revision = layer.put(new MapLayersApi.ObjectSpec("spawn",
    new DomainData.Marker("minecraft:overworld", "Станция", 0, 64, 0,
        0xff55aa55, "home"),
    MapLayersApi.Audience.restricted(Set.of(playerId))), 0);
// Для обновления передать revision; remove("spawn", revision) удаляет объект.
// При отключении интеграции:
owner.close();
```

Поддерживаются `Marker` и `Territory`. Читатель должен одновременно входить в
аудиторию слоя и объекта. `publicAccess()` открывает чтение явно;
`restricted(Set.of())` скрывает объект от всех. Мод отвечает за своевременное
обновление списка UUID при изменении своих правил доступа. Пространства имён
предотвращают случайное смешение владельцев; установленные Java-моды остаются
доверенным кодом одной JVM.

`close()` слоя удаляет его объекты; `close()` владельца — все его регистрации.
Закрытие идемпотентно, старый handle не удалит новый слой с тем же именем.
Выключение модуля карты и остановка сервера очищают реестр и инвалидируют handles.
После включения или запуска зарегистрируйте данные заново. Это временные объекты:
они не сохраняются в БД и не изменяют пользовательские метки и территории.
Интеграция обязана вызвать `close()` при собственном отключении.

Лимиты: 16 слоёв на мод, 256 на сервер, 1024 объекта на слой, 8192 на сервер,
256 UUID в аудитории и 128 вершин территории. Создание требует ревизию 0,
изменение/удаление — актуальную ревизию объекта. Конфликт не перезаписывает данные.

Чтение: `DomainApi.mapLayers(cursor, snapshot)` и
`mapLayerObjects("mod_id:layer", cursor, snapshot)`. Страницы содержат до 64 слоёв
или 8 объектов. Для первой страницы используйте пустой cursor и
`OptionalLong.empty()`; для продолжения — `nextCursor` и `snapshot` ответа.
Изменение реестра делает старый снимок недействительным (`CONFLICT`): начните
чтение заново. Подписки `DomainWatch.MapLayers` и `MapLayerObjects` возвращают
первую страницу актуального снимка. Согласованный клиентский feature `map-integration-layers` включает отображение
этих слоёв на большой карте и миникарте. В окне «Слои» каждый доступный слой
имеет общий для обеих карт переключатель; выбор сохраняется в настройках клиента.
В подсказке указано полное имя `mod_id:layer`. Неизвестная клиенту иконка
отображается как стандартная метка. Сторонние объекты доступны только для просмотра
и не попадают в редактор личных меток или территорий.

Игровая синхронизация использует те же аудитории слоя и объекта. Сервер отправляет
только разрешённые данные авторизованному игроку, без API-ключей. Пакет содержит
до 8 изменений с ограничением размера, неизменные объекты повторно не передаются.
При отзыве видимости клиент сначала очищает прежний набор и затем получает
оставшиеся разрешённые объекты. Закрытие владельца, выключение карты и выход
из авторизованной сессии удаляют его данные. Если подтверждения сервера не приходят
12 секунд, клиент скрывает объекты; пропуск последовательности вызывает повторную
синхронизацию. Координаты и геометрия интеграций не записываются на диск клиента.
