# Обновление Rivet

Обновите мод и вернитесь на сервер.

Кнопка с иконкой Rivet справа от «Сетевой игры» открывает окно обновлений.
Версия Rivet также отображается слева внизу рядом с версиями Minecraft и NeoForge.
Подсказка показывает установленную версию. При обновлении кнопка получает
плавно пульсирующую золотую рамку, а подсказка — строку с доступной версией.
При отключённых анимациях рамка остаётся постоянной.
После установки перезапустите игру.
Фоновая проверка использует сохранённый список версий. Открытие окна обновлений,
проверка обязательного обновления перед входом и кнопка «Повторить» запрашивают
свежий список, не дожидаясь срока обновления кэша. Ограничение запросов источника
при этом сохраняется: Rivet пробует резерв и показывает время ожидания. Если фоновая проверка использовала
сохранённые данные после ошибки сети, каталог помечается как неполный.

Серверы встроенного каталога отображаются в обычном списке серверов Minecraft.
Каталог обновляется вместе с Rivet; его серверы нельзя удалить или изменить
через список. Свои серверы можно добавлять и редактировать как обычно.
Требуемые версии мода и компонентов сборки задаёт сервер.

Клиент Rivet должен быть не старее серверного в той же основной ветке.
Например, сервер 2.3.0 принимает клиент 2.3.0 или 2.3.1 при совместимых сетевых
протоколах; клиент 1.x не подходит.
При подключении к серверу с поддержкой предварительной проверки Rivet показывает
своё окно обновления до входа в игру. В обзоре перечислены изменения мода и сборки;
они применяются вместе после подтверждения и закрытия игры. Дождитесь завершения
установки, затем запустите Minecraft своим лаунчером и подключитесь снова.
Повторный запуск нужен один раз для всего набора; уже установленные файлы
повторно скачивать не требуется. При ошибке применения
откатывается весь набор. Сервер не может подменить источник обновления Rivet:
JAR должен соответствовать официальному выпуску. При подключении Builder может
передать проверенную копию серверного Rivet через прямой адрес или прокси. Клиент
проверяет подпись выпуска и полный хеш JAR перед установкой. Если серверная копия
недоступна, используются внешние источники.

Из главного меню список версий берётся из подписанного статического каталога
с резервным адресом. GitHub API используется только как запасной источник.
Для подписанного выпуска доступны официальный файл и зеркала; неверная подпись
или повреждённый файл не допускаются к установке.

Если часть списка версий недоступна, окно сообщает об этом. Уже проверенные версии
остаются доступны; без выбранной версии кнопка «Повторить» обновляет список.
Старые серверы без предварительной проверки сохраняют прежнее окно отказа подключения
с выбором подходящей версии.

Ошибка сети, ограничение запросов и недоступное описание выпуска не означают,
что совместимой версии нет. При обязательном обновлении окно отличает сбой
проверки от полного ответа без подходящего выпуска и показывает версии клиента,
сервера, NeoForge и Java. Подробная причина сбоя сохраняется в `logs/latest.log`.
