# API: ключи и доступ

<a id="ключи-api-приложений"></a>

Ключи управляются **только через локальную консоль сервера**. Игровые команды,
OP, LuckPerms `*`, командные блоки и RCON не предоставляют этот доступ.
Ключей по умолчанию нет. Управление ключами не открывает HTTP-порт; сетевой
REST/WebSocket-транспорт подключается отдельно.

```text
rivet api keys scopes
rivet api keys create website "server.status.read,server.status.subscribe" 30 120
rivet api keys list
rivet api keys disable <UUID>
rivet api keys enable <UUID>
rivet api keys rotate <UUID> 30
rivet api keys revoke <UUID>
rivet api keys limit website 120
```

`create`: ID приложения (2–64 символа, латинские строчные буквы, цифры, `_`, `-`;
первый символ — буква), scopes через запятую в кавычках, срок в днях, лимит ключа в минуту.
Нельзя выдавать `*` или неизвестные scopes. Актуальный список показывает
`rivet api keys scopes`; выдавайте только права нужных приложению операций.
Доступны отдельные права чтения, изменения, подписок, сессий, серверного управления
и рендера карты. Полные контракты описаны в [REST](../api/rest.md)
и [WebSocket](../api/websocket.md). Для каждого приложения создаётся
общий бюджет `api.requestsPerMinute`; дополнительные ключи его не увеличивают.
`limit` меняет общий бюджет существующего приложения, сохраняя уже использованный
счётчик текущей минуты. Действует меньший доступный бюджет: ключа и приложения.

Консоль выводит UUID и путь `rivet/api-keys/<UUID>.secret`, **не секрет**.
Прочитайте файл локально, перенесите секрет в защищённое хранилище приложения,
затем удалите файл. Обычный файл не уничтожается автоматически после чтения.
На POSIX каталог защищён правами `0700`, файл — `0600`; на ACL-файловой системе
доступ ограничивается владельцем каталога сервера. Если защищённое создание
не поддерживается, выдача прекращается. Символические ссылки в каталоге выдачи
не допускаются; существующий файл не перезаписывается.

В PostgreSQL сохраняется SHA-256 проверочное значение случайного 256-битного
секрета, scopes, срок, последнее использование и состояние. Сам секрет не
сохраняется в БД. `list` не показывает секрет или его хеш. Не помещайте секрет
в команды, URL, исходники сайта и журналы. Для сетевых запросов нужен защищённый
Authorization header; постоянный ключ не предназначен для браузерного JavaScript.

`disable` временно закрывает доступ, `enable` восстанавливает неистёкший и
неотозванный ключ. `revoke` необратим. `rotate` создаёт новый секрет с прежними
scopes/лимитом и одновременно отзывает старый; периода перекрытия нет.
Если выдача нового секрета завершается ошибкой до фиксации транзакции, старый
ключ сохраняется. Команды отзыва/ротации удаляют старый файл выдачи, если он ещё
существует. Очередь команд ограничена; `BUSY` означает, что запрос надо повторить.

## Лимиты ключей

Параметры `[api]` применяются после перезапуска сервера:

| Параметр | По умолчанию | Назначение |
| --- | --- | --- |
| `keyLimit` | 256 | Максимум сохранённых записей ключей, включая отозванные до очистки |
| `appKeyLimit` | 8 | Максимум неистёкших и неотозванных ключей приложения, включая отключённые |
| `requestsPerMinute` | 120 | Начальный общий бюджет нового приложения |
| `maxKeyDays` | 365 | Максимальный срок при выдаче или ротации |
| `keyRetentionDays` | 30 | Хранение метаданных после истечения/отзыва |
| `auditEntries` | 10000 | Максимум записей отдельного журнала управления ключами |

Очистка старых записей и файлов недействующих ключей выполняется перед новой
выдачей. При достижении `keyLimit` выдача, включая ротацию, отклоняется до
освобождения места или повышения лимита. Журнал фиксирует создание, ротацию,
отзыв, отключение, включение и изменение лимита без секретов и содержимого чата.
