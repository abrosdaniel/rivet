# Серверный рендер карты

## Включение и лимиты

`[api.terrain]` создаёт отдельное изображение поверхности мира для внешних
приложений. Веб-интерфейс не входит в мод. Это не обмен исследованной картой
игроков: клиентские карты и их файлы не используются.

По умолчанию `enabled = false`. При включении:

- `dimensions` — разрешённые измерения, по умолчанию только `minecraft:overworld`.
- `minX`, `minZ`, `maxX`, `maxZ` — включительные границы публикации в блоках,
  по умолчанию от −2048 до 2047 по обеим осям.
- `hidden` — скрытые прямоугольники в формате `"minX,minZ,maxX,maxZ"`, до 64.
  Они маскируются до сохранения PNG и на всех обзорных масштабах.
- `maxZoom = 4` — число обзорных уровней (0–6). Поверхность использует тайлы
  256×256 пикселей на 16×16 блоков при уровне 0; каждый следующий уровень
  охватывает вдвое большую область по каждой оси.
- `maxTiles = 4096` — лимит сохранённых PNG каждого профиля (64–65536). При переполнении
  удаляются старые тайлы; их запросы вернут 404 до повторного рендера.
- `radius = 4` — радиус обхода вокруг игроков в чанках (0–16).
- `columnsPerTick = 64` — максимум снимаемых столбцов за тик (1–256).
- `budgetMicros = 1000` — мягкий бюджет снятия данных за тик, в микросекундах
  (100–5000). PNG и обзорные уровни строятся в отдельном ограниченном потоке.

Автоматический обход вокруг игроков использует уже загруженные чанки.
Запросы API не загружают и не генерируют мир. Ручная задача охватывает до 4096 чанков и пропускает незагруженные; одновременно
выполняется одна задача. Полный рендер сохранённых регионов без игроков запускается отдельно через API.
Поверхность использует текстуры и геометрию блоков с окраской биомов
при постоянном дневном освещении. Пещеры доступны через отдельные приватные профили.

PNG и постоянный идентификатор мира хранятся в `rivet-terrain/` внутри папки мира.
Готовые изображения доступны после перезапуска без повторной отрисовки. Изменение
области публикации или масок создаёт новое поколение кэша: старое больше не выдаётся.
Права ключа `map.tiles.read` и `map.render.manage` позволяют соответственно читать
тайлы и управлять задачами. Ключи выдаются только через серверную консоль. Для
сайта используйте собственный backend; не передавайте секрет посетителю браузера.

## Полный рендер сохранённого мира

Полный обход: `POST /api/v1/map/terrain/jobs/saved`, тело `{}`,
право `map.render.manage`; из Java — `TerrainApi.renderSaved()`. Обход охватывает
существующие регионы разрешённых измерений в пределах `minX/minZ/maxX/maxZ`.
Ограничение в 4096 чанков относится только к ручной задаче загруженной области.
При обычном первом запуске полный обход не запускается; после аварийного завершения
или переполнения очереди изменений выполняется сверочный проход сохранённой области. Снимки читаются через серверное хранилище,
без загрузки чанков, генерации, создания сущностей и принудительного сохранения мира.
Несохранённые изменения появятся после обычного сохранения и следующего обхода.

До окончания обхода `total = -1`, затем — число просмотренных позиций чанков;
пустые позиции и незавершённая генерация учитываются в `skipped`. Состояние `READING`
означает чтение сохранений. Повреждённый чанк или ошибка чтения завершает задачу
как `FAILED`, не заменяя прежний тайл повреждёнными данными. Отмена использует
обычный endpoint задачи. Лимит `maxTiles` сохраняется и при полном обходе: для
удержания всей области нужен достаточный бюджет производного кэша.
