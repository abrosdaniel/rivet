# Включение HTTP API

Настройте адрес, порт и доступ приложений.

REST включается в `[api.http]` файла `config/rivet-server.toml` и применяется после
перезапуска сервера. Веб-интерфейс приложение предоставляет самостоятельно.

| Параметр | По умолчанию | Назначение |
| --- | --- | --- |
| `enabled` | `false` | Запуск HTTP; при отключении порт и обработчики не создаются |
| `bind` | `"127.0.0.1"` | Только loopback: `127.0.0.1` или `::1` |
| `port` | 24464 | Локальный HTTP-порт |
| `connections` | 32 | Максимум принятых соединений |
| `connectionsPerAddress` | 16 | Максимум соединений одного адреса |
| `workers` | 2 | Обработчики вне игрового потока |
| `queue` | 32 | Максимум ожидающих обработку соединений |
| `timeoutSeconds` | 10 | Полный срок соединения, включая ожидание и чтение заголовков |
| `requestsPerMinute` | 600 | Общий входной бюджет до обращения к БД |
| `addressRequestsPerMinute` | 120 | Входной бюджет одного фактического адреса |
| `origins` | `[]` | Точные HTTPS origins браузерных сайтов, без пути и завершающего `/` |
| `publicResources` | `[]` | Ресурсы, разрешённые без ключа |

Для внешнего доступа настройте собственный reverse proxy с HTTPS и upstream на
локальный порт Rivet. Не публикуйте локальный HTTP через незащищённый туннель.
Передавайте Authorization, отключите журналирование этого заголовка и не кэшируйте
закрытые ответы в общем кэше. Ограничьте подключения и запросы также на proxy.
Rivet не доверяет `X-Forwarded-For`: запросы через один proxy делят адресный бюджет.
Пример конфигурации: [HTTPS/WSS через Nginx](reverse-proxy.md).

REST предоставляет статус, доменные данные, операции и серверную карту:
[контракт и примеры REST](../api/rest.md). Личные данные требуют
сессии игрока, административные действия — соответствующих прав.
Анонимно можно открыть только статус сервера, его изменения, capabilities и OpenAPI.
Например, `publicResources = ["server.status"]` разрешает анонимное чтение только
статуса. Остальные идентификаторы: `capabilities`, `server.status.events`, `openapi`.
Для браузерного сайта дополнительно нужен его точный адрес в `origins`, например
`["https://status.example.org"]`. Постоянные ключи храните только на backend сайта;
Origin-запросы с таким ключом отклоняются.
