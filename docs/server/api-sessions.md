# Вход на сайты

Разрешите доверенному приложению работать от имени игрока.

Доменный REST доступен backend приложения по отдельным scopes: `groups.read`,
`events.read`, `board.read`, `polls.read`, `ideas.read`. Ключ сам по себе видит только
данные, доступные обычному читателю; он не является игроком или администратором.
Игровые разделы должны быть включены. Публичная HTTP-выдача этих доменов не включается
через `publicResources`: требуется ключ. Коллекции не содержат UUID участников,
заявки, приглашения, ответы, голоса, историю модерации и настройки.

Выдавайте `sessions.password` только доверенным приложениям: их backend получает
введённый игроком пароль. Он должен передать его Rivet по HTTPS, не сохранять и не
журналировать. При включённом Auth доступен `POST /api/v1/sessions/password` с JSON
`login` и `password`. Используются канонический UUID Auth, проверка пароля, блокировка
и ограничение попыток. Указать произвольный UUID вместо пароля нельзя.

При `auth.mode = "false"` выдайте приложению `sessions.link`. Сайт запрашивает
`POST /api/v1/sessions/link` с `{}`, показывает игроку команду
`/rivet link <code> <application>`, а backend хранит отдельный `pollToken`.
Игрок выполняет команду сам на сервере, проверив название приложения. Затем backend
получает сессию через `POST /api/v1/sessions/exchange` с `code` и `pollToken`.
Код действует пять минут, обмен одноразовый; один код без pollToken не выдаёт сессию.
Привязка не выдаёт игроку ключ приложения.

Для чтения от имени игрока приложение отправляет одновременно свой Bearer-ключ и
`X-Rivet-Session`. Членство и видимость проверяются при каждом чтении. Сессия не
переносится на другой ключ. Отзыв/отключение/истечение ключа прекращает доступ;
при Auth также проверяются блокировка аккаунта и поколение его учётных данных.
Игрок отзывает все внешние сессии командой `/rivet unlink`.

В `[api]` параметры `sessionHours = 24` (1–720) и `sessionLimit = 1024` (1–10000)
задают срок и общий предел. На игрока и ключ — не более десяти сессий. Сессии и
ожидающие привязки хранятся в памяти в виде хешей; **перезапуск сервера завершает их**.
Браузер не получает постоянный API-ключ: сайт хранит ключ и сессию Rivet на backend,
а вход пользователя в сайт организует собственным защищённым cookie.
