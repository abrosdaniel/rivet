# Регистрация и вход

| `[auth] mode` | Способ входа                                                  |
| ------------- | ------------------------------------------------------------- |
| `"false"`     | Auth выключен; действуют правила Minecraft.                   |
| `"base"`      | Пароль аккаунта на сервере.                                   |
| `"hybrid"`    | Пароль и возможность привязать официальный Minecraft-аккаунт. |

`registration` разрешает регистрацию; `minPasswordLength` задаёт минимум **нового** пароля: 6–128 символов, по умолчанию 6. Старые пароли продолжают работать.

`online-mode` в `server.properties` настраивается отдельно: для игроков без официального аккаунта нужен `false`; при `true` Minecraft сначала проверяет официальный аккаунт.

Вход проходит до загрузки мира. Смена пароля, привязка аккаунта и отзыв сохранённых устройств — в **F8 → Главная → Безопасность** в карточке профиля. В компактном окне откройте **⋯ рядом с поиском → Безопасность**. Пароли хранятся как хеши Argon2id; при включённом Auth игровой TCP-трафик защищён TLS 1.3.

## Восстановление доступа

1. Убедитесь, что обращается владелец аккаунта.
2. Выполните в консоли `rivet auth reset PlayerName`.
3. Скопируйте код из ответа консоли и передайте владельцу лично. При сбросе из игры код видит только запросивший администратор — в окне с кнопкой копирования.
4. Игрок вводит код и новый пароль в форме восстановления.

Код одноразовый, действует **15 минут**; новый отменяет предыдущий. В PostgreSQL хранится только хеш и срок действия, автор выдачи — в журнале без кода. Файлы не создаются. Ответ консоли может сохраняться в её логах. Сброс отзывает устройства и сеансы, удаляет официальную привязку. В игре для сброса нужны вход через Auth и отдельное право `rivet.auth.reset`; OP и `rivet.admin` его не заменяют.

## Смена ника

Игрок должен выйти с сервера, включая экран авторизации. В консоли выполните:

```text
rivet auth rename Danissimo7 Daniss1mus
```

В игре используется `/rivet auth rename <старыйНик> <новыйНик>`. Команда доступна
авторизованному администратору с OP уровня 2 или правом `rivet.admin`. Auth должен
быть включён. Для ников допустимы 1–16 латинских букв, цифр и символов `_`.
Занятый или зарезервированный ник использовать нельзя; изменить только регистр можно.

Дождитесь подтверждения с новым именем и сохранённым UUID. Игрок меняет ник в
лаунчере и входит с прежним паролем. Сохранённые устройства, коды восстановления
и прежние сессии отзываются; официальная привязка и блокировка аккаунта сохраняются.

UUID остаётся прежним: инвентарь, достижения, статистика, права LuckPerms и данные
Rivet не переносятся в новый аккаунт. Сервер обновляет имя в профиле, whitelist,
списках OP и банов, а также очки и команду scoreboard. История сообщений и аудит
сохраняют имена на момент события. Сторонние моды, которые хранят данные **по нику**,
а не UUID, требуют собственной проверки; команда не переписывает их файлы.

Если сервер остановится во время операции, её незавершённая часть будет восстановлена
при запуске. При сообщении об ошибке обновления серверных списков проверьте журнал:
имя в БД уже могло измениться, повторять команду вручную не нужно.

## Приложения и сайты

В окне **Безопасность → Приложения и сайты** игрок видит собственные сессии API.
Можно завершить отдельную сессию или все сразу, сохранив вход в игру и устройства.
Отозванные ключи и истёкшие сессии не показываются. При выключенном Auth все
привязки внешних приложений можно отозвать командой `/rivet unlink` в игре.
Перезапуск сервера завершает все сессии сайтов.

## Двухфакторная защита

В **Безопасность → Двухфакторная защита** игрок вводит пароль, добавляет секрет
в приложение-аутентификатор (TOTP, 6 цифр, 30 секунд) и подтверждает кодом.
При включении выдаются десять одноразовых резервных кодов. Их нужно сохранить:
повторно посмотреть коды нельзя, но можно создать новый набор, отменив прежний.

В `[auth]` настройте `totp`:

| Значение | Для кого обязательна защита |
| --- | --- |
| `"optional"` | Игрок включает её по желанию; значение по умолчанию. |
| `"staff"` | OP и аккаунты с `rivet.admin`, `rivet.permissions.manage`, `rivet.auth.reset`, `rivet.restart`, `rivet.maintenance` или `rivet.pack`. Проверяется постоянный контекст LuckPerms. |
| `"all"` | Все аккаунты Rivet Auth. |

Обязательную защиту можно настроить до входа в мир. При выключенном Auth эта
политика не применяется. Включённый TOTP проверяется также при официальном входе,
входе с сохранённого устройства и через API. Сброс пароля не отключает TOTP.
Смена ника сохраняет защиту и резервные коды за UUID. Изменение защиты отзывает
другие сессии и сохранённые устройства.

Если потеряны приложение и резервные коды, после проверки личности владельца
выполните **только в серверной консоли**:

```text
rivet auth reset-totp ИмяИгрока
```

Операция записывается в аудит и отзывает сессии. При обязательной политике игрок
снова настраивает TOTP перед входом. Секреты зашифрованы в PostgreSQL, ключ хранится
в `rivet/auth-factors.key`. Сохраняйте этот файл вместе с резервной копией сервера,
отдельно от публичных файлов сборки. Без прежнего ключа коды приложения нельзя
проверить; не удаляйте и не заменяйте его при обновлении.
