# Настройки сервера

Все настройки — в `config/rivet-server.toml`. [Полный шаблон с пояснениями](../../rivet/core/src/main/resources/rivet-server.toml). Имена параметров сохраняйте как в шаблоне; меняйте значения справа от `=`. Строки заключайте в кавычки, целые числа и `true`/`false` пишите без кавычек. `auth.mode = "false"` — строка, поэтому кавычки обязательны.

Разделы `[menu]` и `[community]` можно применить без перезапуска: откройте настройки сервера в администрировании, нажмите **«Проверить файл заново»**, просмотрите изменения и выберите **«Применить меню и разделы»**. Для остальных настроек нужен полный перезапуск сервера.

Обязательные разделы `[connection]`, `[auth]`, `[database]` сохраняйте со всеми параметрами. Пропущенные необязательные параметры получают значения из шаблона. При запуске недостающие настройки автоматически добавляются в файл вместе с пояснениями. Ваши значения и комментарии сохраняются; перед дополнением создаётся резервная копия `config/rivet-server-*.toml.bak`. Неизвестные параметры и неверные типы или диапазоны останавливают запуск; значения паролей в ошибках не выводятся.

| Раздел | Назначение |
| --- | --- |
| `[connection]` | Время ответа клиента при входе. |
| `[auth]` | Способ входа, регистрация, пароль и политика TOTP. |

| `[community]` | Состав меню, типы и лимит объединений. |
| `[menu]` | Текст помощи и ссылки в «Помощи». |
| `[groups]` | Объединения, участники, заявки и общие места. |
| `[reports]` | Обращения и модерация Rivet. |
| `[server]` | Объявления, обслуживание и запланированная остановка. |
| `[retention]` | Сроки хранения обращений и корзины, предел журнала. |
| `[spark]` | Пороги нагрузки и частота предупреждений. |
| `[trade]` | Обмены и подарки: срок, число исходящих предложений, позиции, расстояние и измерение. |

| `[map]` | [Карта, видимость игроков и ограничения](map.md). |
| `[api]`, `[api.http]`, `[api.websocket]` | [API: ключи, лимиты и сетевой доступ](api.md). |
| `[api.terrain]` | [Серверный рендер карты](terrain.md). |
| `[updates]` | Уведомления об обновлениях Rivet в консоли. |

| `[pack.network]` | Адрес и TCP-порты раздачи. |

Старые разделы `[tasks]`, `[storage]`, `[board]`, `[events]`, `[polls]`, `[ideas]`
удаляются из конфига при обновлении с резервной копией исходного файла.
Это не удаляет сохранённые данные из базы и не включает прежние механики.

### Скины и плащи HD

В `[skins]` параметр `maxResolution` задаёт максимальную ширину скина,
`maxCapeResolution` — плаща. Допустимые значения: `64`, `128`, `256`, `512`, `1024`.
Оба значения по умолчанию — `256`: скин до 256×256, плащ до 256×128.
Скины квадратные; старый формат с половинной высотой автоматически преобразуется
в квадратный без уменьшения детализации. Плащи всегда имеют пропорции 2:1.

Для скинов 1024×1024 и 1024×512 установите `maxResolution = 1024`.
Для плащей 1024×512 — `maxCapeResolution = 1024`. Изменения требуют перезапуска
сервера; при снижении лимита уже сохранённые изображения остаются доступны.
Новые параметры добавляются в конфиг автоматически с резервной копией.

`maxSizeMiB` отдельно ограничивает размер файла скина. `capes` разрешает статичные PNG-плащи.
`maxCapesPerPlayer` задаёт количество сохранённых плащей (1–8, по умолчанию 8),
`maxCapeSizeKiB` — размер входного PNG (16–1024 КиБ, по умолчанию 256).
`maxOutfitsPerPlayer` ограничивает число образов «скин + плащ» (1–8, по умолчанию 8).
`enabled = false` отключает весь модуль внешности. Отключение плащей сохраняет
библиотеки, но оставляет отображение официального плаща стандартному клиенту Minecraft.

`fallback` применяется к официальному скину и плащу вместе: `"UUID"` использует
подтверждённый Mojang UUID, `"nickname"` — поиск по нику, `"false"` отключает
серверное получение внешности Mojang. Официальный плащ кэшируется отдельно
от библиотеки игрока и не расходует `maxCapesPerPlayer`.

При обновлении Rivet очищает конфиг от настроек удалённых функций и их пунктов
в `community.sections`. Перед записью создаётся резервная копия рядом с файлом.
Действующие значения сохраняются; эта очистка не удаляет записи из базы данных.

Триггеры чата настраиваются в `[chat]`:

```toml
globalTrigger = "!"
groupTrigger = "#"
localTrigger = ""
personalTrigger = "@"
personalName = "Лично"
personalColor = "#78C98D"
```

Например, `globalTrigger = "!!"` и `groupTrigger = "##"` дают
`!!Привет` для общего чата и `##Город: Привет` для объединения.
Непустой триггер содержит 1–8 символов без пробелов, двоеточия и начального `/`. Триггеры
не должны совпадать или начинаться друг с друга. Нужен полный перезапуск сервера.

Текст предупреждения для пустого локального чата задаётся там же:

```toml
localEmptyMessage = "Рядом нет игроков. Для общего чата начните сообщение с {globalTrigger}"
```

Предупреждение приходит после каждого сообщения, которое не услышал другой
авторизованный игрок в радиусе локального чата и том же измерении.
`{globalTrigger}` автоматически заменяется текущим триггером общего чата.
Допустимо 1–512 символов обычного текста без переводов строк.

`localTrigger = "~"` позволяет явно выбрать «Рядом»: `~Привет`. Пустая строка у любого канала
делает его каналом без префикса. Пустым может быть только один триггер; два пустых
значения останавливают запуск. Например, `globalTrigger = ""` и `localTrigger = "~"`
делают общий чат основным, а `~Привет` — локальным сообщением.
При `groupTrigger = ""` используется `Название: текст`. Если все четыре триггера
непустые, обычный текст остаётся локальным при `local = true`;
при выключенном локальном канале сообщение с явным локальным триггером не
перенаправляется в общий чат. Правила уникальности действуют для всех четырёх триггеров.

Личный канал использует `personalTrigger` (по умолчанию `@Ник: текст`),
`personalName` и `personalColor` (по умолчанию зелёный). Его триггер тоже может
быть пустым, если остальные непустые. Клиент отправляет сокращение через
стандартную команду `/msg`; `/msg`, `/w` и `/tell` сохраняют обработку Minecraft.
Rivet меняет только оформление стандартных личных сообщений, не заменяя
доставку, подписи и проверки команд. Личные сообщения не публикуются в API
или серверной истории чата Rivet; сторонние моды журналирования настраиваются отдельно.

## Обмены

`trade.enabled` разрешает новые обмены и изменение активных предложений.
После отключения игроки могут отменить старое предложение и забрать свои вещи
либо получить предметы уже завершённого обмена.

`trade.days` задаёт срок предложения, `maxOutgoing` — число активных исходящих
предложений игрока, `maxPositions` — число различных позиций в его лотке.
`radius = 0` и `sameDimension = false` позволяют согласовывать обмен с офлайн-игроком.
При ограничении расстояния или измерения для подтверждения нужны оба игрока онлайн.

Предметы обменов и журнал незавершённой передачи находятся в
`<папка мира>/rivet/trades/`. Резервируйте и восстанавливайте их вместе с
`<папка мира>/playerdata/` при остановленном сервере: эти данные образуют единое
состояние передачи предметов. Не удаляйте журнал для обхода ошибки хранилища.
При ошибке записи обмены приостанавливаются до восстановления; сервер не
выдаёт предметы из неподтверждённого состояния.
