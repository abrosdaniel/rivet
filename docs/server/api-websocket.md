# Включение WebSocket

Настройте соединения и одноразовые tickets для браузера.

Для WebSocket включите `[api.websocket] enabled = true`. По умолчанию слушатель
выключен; адрес `127.0.0.1`, порт `24465`, максимум 16 соединений (настройка
`connections`, 1–32), общий бюджет `requestsPerMinute = 600`. Не используйте один
порт для HTTP и WebSocket. Для входа игроков и браузерных подключений оставьте
HTTP включённым: через него выдаются сессии и одноразовые tickets. Перезапуск
сервера завершает ранее выданные сессии.

Ключу требуется `websocket.connect`, для подписки на статус — ещё
`server.status.subscribe`. Доменные чтения и команды требуют своих scopes.
Backend подключается с Bearer; браузер подключается через одноразовый ticket,
выданный backend. Постоянный ключ не передаётся в браузер.
Внешний доступ организуется через WSS reverse proxy владельца. История статуса,
повторы команд, ограничения и закрытие соединений описаны в
[протоколе WebSocket](../api/websocket.md).

Подписки и операции используют права соответствующего ресурса и текущие права
связанного игрока. Для административных действий онлайн-присутствие не требуется:
офлайн проверяется статический контекст LuckPerms либо OP. Позиции игроков
и Waystones, напротив, требуют присутствия и авторизации в игре.

Выбор прав приложения и маршруты — в [REST API](../api/rest.md), формат сообщений
и восстановление соединения — в [WebSocket API](../api/websocket.md).
[Java API](../api/java.md) для установленных модов работает без сетевого слушателя
и ключа приложения.

## Браузерные WebSocket tickets

Для прямых подписок браузера добавьте точный HTTPS origin сайта в `api.http.origins`.
Backend получает ticket через HTTP с ключом (`websocket.ticket`, `websocket.connect`
и scopes нужных ресурсов) и сессией игрока. Без настроенных origins браузерные подключения запрещены.

В `[api.websocket]` доступны автоматически добавляемые настройки:

| Параметр | По умолчанию | Ограничение |
| --- | --- | --- |
| `ticketSeconds` | 30 | Время предъявления, 5–120 секунд |
| `ticketLimit` | 1024 | Ожидающие tickets всего, 1–10000 |
| `ticketsPerKey` | 16 | Ожидающие tickets ключа, 1–ticketLimit |

Это лимиты ожидающих подключений, не увеличение `connections`. Ticket одноразовый;
после рестарта нужен новый. Сессия игрока остаётся на backend. Отзыв ключа/сессии
закрывает активные подключения. Через браузер разрешены только подписки,
привязанные к этому игроку; изменения выполняет backend. Используйте WSS и
не журналируйте Sec-WebSocket-Protocol, Authorization и X-Rivet-Session.
