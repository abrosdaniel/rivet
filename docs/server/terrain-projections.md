# Проекции и ресурсы

Выберите вид карты и подключите локальные текстуры.

В `[api.terrain]` параметр `isometric = true` включает дополнительный объёмный
профиль. По умолчанию он выключен. Внешнее приложение выбирает его через
`profile=isometric`; Java — через `terrain.profile("isometric")`, WebSocket —
через тему `map.tiles.isometric`.

Профиль строит геометрию блоков с высотой, перекрытием и прозрачностью
воды, стекла и листвы. Тайлы 256×256 имеют отдельный кэш и события обновления;
проекция указана в metadata. Ручной и полный сохранённый рендер обновляют оба
включённых профиля. Загрузка или генерация чанков для этого не требуется.

Текстуры и стандартные JSON-модели берутся из assets модов и локальных ресурсов.
Недоступные модели отображаются кубами в цветах блоков и биомов. Включение увеличивает расходы
CPU, памяти и диска. `maxTiles` ограничивает PNG каждого профиля отдельно и число
сохранённых изометрических снимков чанков. При заполнении лимита снимков новая
задача завершится ошибкой; уже готовые изображения сохранятся. Исходные данные
изометрии находятся в `rivet-terrain/isometric/` и являются производным кэшем.

## Ресурсы серверной карты

Разместите разрешённые к использованию ресурсы в `rivet/terrain-resources/`:
каждый ZIP/JAR или подкаталог должен содержать `assets/<namespace>/...`. Можно
использовать локальный клиентский JAR Minecraft 1.21.1 как источник ванильных assets.
Rivet ничего не скачивает и не раздаёт исходные текстуры через API. Assets установленных
модов подключаются автоматически; локальные пакеты перекрывают их в порядке имён
(более поздний имеет приоритет). Вложенные ZIP не распаковываются.

После изменения ресурсов перезапустите сервер и запустите рендер через API. Хеш
ресурсов создаёт новое поколение тайлов; старый кэш не выдаётся как новая карта.
При наличии ресурсов изометрия использует более подробную проекцию, поэтому
приложение должно читать `projection` из metadata. Вид сверху отрисовывает геометрию
и текстуры с глубиной и прозрачностью: 16 пикселей на блок, тайл 256×256 на чанк.
Пещерные профили сохраняют обзорное разрешение один пиксель на блок.

Поддерживаются наследование моделей, варианты состояний, multipart, UV, повороты
элементов, root transforms и составные модели NeoForge, биомная окраска травы/листвы/воды.
Варианты моделей выбираются по координатам и сохраняются при перезапуске. Вода и лава
учитывают уровень, соседние поверхности и текстуры потока; внутренние грани жидкости
не рисуются. Скрытые области не участвуют в расчёте соседей. Анимированные текстуры представлены
первым указанным кадром. Клиентские custom loaders и динамические block entities
требуют серверного поставщика геометрии. Диагностика `materials` в metadata API
показывает активность, счётчики и до 100 примеров отсутствующих/неподдерживаемых моделей.
Описание форматов и лимитов: [материалы карты](../api/terrain-materials.md).
