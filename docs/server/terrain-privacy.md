# Приватные карты и маски

Ограничьте доступ к картам и скройте области мира.

Профиль задаётся владельцем в `[api.terrain]`, применяется после перезапуска сервера
и имеет отдельные изображения, промежуточный кэш и поток изменений. Пример полей
этого раздела (не создавайте второй `[api.terrain]`):

```toml
# Запрет для всех профилей, включая приватные:
hidden = ["100,100,115,115"]
# Дополнительный запрет только для общих surface и isometric:
publicHidden = ["0,0,15,15"]
# Приватные профили не наследуют publicHidden; hidden внутри профиля добавляется к глобальному.
profiles = [{id = "staff", projection = "surface", hidden = []}, {id = "builders", projection = "isometric", hidden = ["-32,-32,-1,-1"]}]
```

Прямоугольники включают границы: `minX,minZ,maxX,maxZ`, в блоках, во всех разрешённых
измерениях. Границы карты и глобальный `hidden` действуют всегда. Не более четырёх
приватных профилей; ID — строчная латинская буква, затем до 31 буквы, цифры, `_` или `-`.
`surface` и `isometric` зарезервированы. Проекция приватного профиля может быть
`surface`, `isometric` или `cave`; приватная изометрия работает и при выключенной общей.
`maxTiles` ограничивает кэш каждого профиля; несколько профилей увеличивают расход
диска и CPU. Снимок чанка берётся один раз и используется всеми профилями.

Для выдачи профиля `staff` добавьте конкретному ключу scope
`map.tiles.profile.staff` вместе с `map.tiles.read`. Команда `rivet api keys scopes`
показывает scopes настроенных профилей. Общего wildcard-разрешения нет. Ключи
управляются только из консоли; сессия игрока и LuckPerms для чтения рельефа не нужны.
`map.render.manage` управляет общей очередью рендера всех профилей, а не отдельной
очередью выбранного профиля; не выдавайте его ключам, которым требуется только чтение.

Маски применяются до сохранения PNG/voxel-данных, проекции и обзорных масштабов.
При изменении маски меняется поколение кэша, старые изображения не выдаются;
при запуске возобновляется проход по сохранённому миру без генерации новых чанков.
Существующие старые PNG предыдущего поколения удаляются при открытии своего кэша.
Удалённый из конфигурации профиль недоступен через API; его каталог может оставаться
на диске для ручной очистки владельцем. Каталог мира `rivet-terrain` нельзя публиковать
статическим HTTP-сервером: доступ должен проходить через авторизацию Rivet.

Приватные PNG имеют `Cache-Control: private, no-store` и `Vary: Authorization`.
Не переопределяйте эти заголовки общим CDN-кэшем. Уже скачанные изображения нельзя
отозвать у получателя: отзыв ключа запрещает последующие чтения и подписки.
Маски рельефа не меняют отдельно заданную видимость меток, территорий и игроков.

## Пещерные профили серверной карты

Пещерная карта доступна только как явно настроенный приватный профиль. В существующем
`[api.terrain]` добавьте запись в `profiles`, например:

```toml
profiles = [{id = "deep_caves", projection = "cave", minY = -64, maxY = 0, hidden = []}]
```

`minY` и `maxY` обязательны и включительны: диапазон от 4 до 256 блоков в пределах
−2048…2047. Они задают фиксированный слой, а не положение конкретного игрока.
У ключа должны быть `map.tiles.read` и `map.tiles.profile.deep_caves`. Право на обычную
карту пещеры не открывает; сессия игрока и LuckPerms для этого не требуются.
Пещерные профили учитываются в общем лимите четырёх приватных профилей.

Рендер показывает самый верхний пол полости внутри заданного диапазона: над полом
должны быть как минимум два блока воздуха и непрозрачная крыша в том же диапазоне.
Открытая поверхность, сплошной камень и участки без подходящей полости прозрачны.
Если крыша выше `maxY`, расширьте диапазон или создайте другой профиль. Это вид сверху
на выбранный слой, без автоматического переключения по глубине игрока. Цвет пола
берётся из блока, биома и локальных материалов; динамический свет факелов не моделируется.

Глобальные и профильные маски действуют до записи тайлов и обзорных масштабов.
Полные подземные снимки для пещер не сохраняются: остаются только PNG выбранного
слоя. Изменение диапазона высот меняет поколение кэша, старые тайлы не выдаются.
Метаданные API содержат `projection.profile = "cave"` и `slice: {minY, maxY}`.
Пещеры используют общие задания, обновления изменённых чанков и восстановление очереди;
полный рендер читает сохранённый мир без загрузки или генерации новых чанков.
Новые профили требуют перезапуска сервера.
