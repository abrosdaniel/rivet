# Внутренние модули

Rivet устанавливается одним JAR. Клиентские и серверные функции регистрируются
через отдельные точки сборки: `ClientModules` и `ServerModules`.
Функция не устанавливает другие функции внутри собственного `install()`.

## Границы

| Часть | Сервер | Клиент | Общие службы |
| --- | --- | --- | --- |
| Основа | ServerIntegration, ServerDatabase | Client, ServerMenuClient | Конфигурация, протоколы, права, транспорт меню |
| Метаданные игроков | ServerSocial | SocialClient | Общие данные для чата, TAB и имён над головой |
| TAB | ServerSocial | RivetTab | Метаданные игроков и участников объединений |
| Имена над головой | ServerSocial | PlayerNameplates | Метаданные игроков |
| Чат | ServerChat | ClientChat, SocialChatControls | Оформление сообщений, метаданные, права каналов |
| Навигация | ServerNavigation | ClientNavigation, DirectionCue, MapLayerClient | Координаты и адаптер карты |
| Скины | ServerSkins | SkinClient | SkinWire, SkinStore |
| Социальная основа | ServerFeatures | Экраны меню, RivetHud | Общие очереди, транзакции, уведомления и UI Kit |
| Объединения, доска, события, голосования, предложения | CommunityModules / DocumentModule | Соответствующие разделы меню | CommunityStore — общая документная модель |
| Задачи | CommunityModules / CommunityTasks | TaskScreen | TaskWorkflow и лимиты задач |
| Хранилища | ServerTaskStocks | Голограммы и ресурсы задач | CommunityTasks, StockHolograms |
| Обращения | ServerReportsModule | ReportScreen, ReportQueueScreen | CommunityReports |
| Управление сервером | ServerManagement | Экран управления сервером | CommunityAdministration, ScheduledAnnouncements |
| Статистика и голосования о нарушениях | ServerPlayerStatistics, ServerModerationVotes | Профиль и голосование | PostgreSQL и права |
| Авторизация | AuthServer | AuthClient | AuthProtocol, AuthStore, AuthTls |
| Клиентские сборки | ServerPack | ServerPackClient, ServerPackScreen | Снимки публикаций, проверка файлов, транзакции установки |

`core` не использует Minecraft/game API и клиентские экраны. Библиотека
`net.neoforged.jarjar` используется для проверки вложенных зависимостей.
`core` содержит логику, контроллеры, хранилища и `ModuleRuntime`. Разделение внутренних функций
не означает публичный API для сторонних модов.

## Серверный жизненный цикл

Конфигурация и PostgreSQL готовятся перед запуском модулей. `ModuleRuntime`
проверяет зависимости до побочных эффектов, запускает функции в порядке
зависимостей и останавливает их в обратном порядке. При ошибке запуска
освобождаются и уже запущенные, и частично созданные ресурсы. Ошибка остановки
одной функции не мешает очистке остальных.

Регистрация событий, команд и сетевых обработчиков происходит один раз при
загрузке мода. Создание хранилищ и рабочих потоков происходит при запуске
сервера. Остановка закрывает очереди, очищает временные данные и освобождает
ссылки на хранилища до закрытия PostgreSQL. Повторная остановка безопасна.

Авторизация не запускается при `auth.mode = "false"`. При `skins.enabled = false`
сервер не создаёт SkinStore и фоновые потоки скинов; обработчик протокола
возвращает состояние недоступности клиенту. При `chat.enabled = false` сообщения
не обрабатываются Rivet и не запускается состояние чата. Статистика и
голосования сохраняют собственные настройки собираемых полей и доступности.

Для частей без серверных ресурсов, например команды навигации, достаточно
регистрации обработчика; создавать фиктивное хранилище или поток не требуется.

## Политика доступности

`FeatureModules` — неизменная политика текущего запуска из `ServerSettings`.
Она проверяет зависимости до запуска ресурсов, фильтрует разделы меню и
проверяет запросы до транзакции, включая повторные запросы с квитанциями.
`CommunityModules` создаёт обработчики только включённых задач и документных
разделов. Общая документная модель и транзакционный слой остаются в
`CommunityStore`; они не являются отдельными подключаемыми JAR.

Обращения, отслеживание запасов и управление сервером имеют отдельных владельцев
ресурсов в `ServerModules`. Выключенные владельцы не запускаются. Обработчики
тиков проверяют наличие ресурса, фоновые чтения захватывают ресурс запуска,
очереди освобождаются после остановки зависимых модулей.

Состояние меню передаёт объект `modules`; новые клиенты проверяют его вместе с
правами и согласованными возможностями. Сервер всё равно проверяет каждый запрос.
Личный scope задач не требует объединений. Запасы требуют задач; выключенные
объединения исключаются из групповых задач и запасов. Очистка и напоминания
учитывают политику, сохраняя записи выключенных функций.

Применение `[menu]` / `[community]` не изменяет политику модулей до перезапуска.
Необязательные интеграции не входят в переключатели функций и активируются автоматически.

## Клиентский жизненный цикл

Обработчики оформления игроков, чата, навигации, скинов и авторизации
регистрируются отдельно. Данные принадлежат соединению: смена сервера очищает
метаданные, историю объединения системных сообщений, маршрут и слои карты.
Открытие чата ускоряет обновление метаданных вместо ожидания фонового интервала.
Скины освобождают динамические текстуры и отменяют запросы; авторизация
закрывает защищённый транспорт при отключении.

Сообщения `social`, `socialDirection` и SkinWire сохраняют свои идентификаторы
и формат. Общий транспорт меню остаётся в ServerMenuClient. Профили,
настройки и формы остаются диалогами; архитектура модулей не меняет навигацию UI.

## Адаптеры

Интеграции используются через серверный CompatibilityRegistry и клиентский
ClientCompatibilityRegistry. Адаптер автоматически активируется при наличии
поддерживаемого API. Отсутствие мода или ошибка его API изолируются внутри
адаптера; отдельные выключатели интеграций не нужны.

## Проверки

- ModuleRuntimeTest проверяет зависимости, отключённые части, частичный запуск,
  откат, ошибки очистки и повторный запуск.
- `:mod:checkModuleComposition` запрещает вложенную регистрацию функций.
- `:bootstrap:verifyBundle` проверяет состав единого JAR и отсутствие тестовых классов.
- Отдельный `:mod:compatibilityTestJar` содержит ModuleLifecycleHarness. В тестовом
  сервере `RIVET_MODULE_SMOKE=default` проверяет создание и освобождение ресурсов;
  значение `disabled` проверяет выключенные чат, скины, авторизацию и функциональные модули, включая отсутствие их ресурсов.
  Сценарий автоматически останавливает тестовый сервер после проверки.
- Клиентские сценарии включаются `-PrivetUiHarness` и проверяют поведение экранов
  Minecraft. Их следует запускать отдельно от обычной сборки поставляемого JAR.

Для проверки очистки соединения используется сочетание
`RIVET_CHAT_IDENTITY_REVIEW=1` и `RIVET_MODULE_CHAT_SMOKE=1` в клиенте.
Серверная ChatMetadataFixture использует только временные узлы LuckPerms;
сценарий телепортации требует прав тестового игрока. После проверки клиент
отключается, проверяет очистку состояния и закрывается.

## Данные серверного меню

Состояние меню содержит `hasLinks`: наличие настроенных ссылок сервера.
Кнопка ссылок находится в «Помощи» и скрыта при пустом списке. Сами ссылки
загружаются запросом `menuData`. Проверка файлов сборки выполняется до подключения.

Ответы документных разделов содержат `trashDays`; подробности удалённой записи
содержат вычисленное `restoreUntil` в миллисекундах Unix. Эта дата не хранится
в документе: изменение серверного срока меняет следующий ответ. Клиент не
подставляет собственные 30 дней при отсутствии этих необязательных полей.

### Источники файлов сборки

Сервер разрешает ссылки поставщиков при публикации, проверяет файлы и хранит
неизменяемые копии. Публикация связывает прямой адрес CDN с размером и SHA-256 файла.
Клиент проверяет внешнюю загрузку и при ошибке получает копию той же публикации
с сервера через новое TLS-соединение с проверкой ключа. Отмена не запускает резервную
загрузку. Локальные файлы не имеют внешнего адреса.

Протокол раздачи `pack` — 2. Поле `url` необязательно; прежние снимки без него
сохраняют свои канонические байты и хеши, их файлы загружаются с сервера.

### Проверка модов сборки

Проверка читает метаданные JAR без запуска модов. Вложенные библиотеки выбираются
штатным JarSelector NeoForge; относительный путь внутри архива не ограничен
папкой `META-INF/jarjar`. Абсолютные пути, переходы между каталогами и повреждённые
архивы отклоняются; сообщения содержат файл-владелец и вложенный путь.

Контейнеры `FMLModType: LIBRARY` предоставляют моды через вложенные JAR. Типы
зависимостей читаются без учёта регистра; отсутствующий тип означает обязательную
зависимость, а прежнее `mandatory = false` — необязательную. Для Minecraft 1.21.1
учитывается матрица FancyModLoader: совместимые версии Minecraft 1.21 и NeoForge
21.0.166. Правила применяются к метаданным всех модов, без исключений по именам.
Проверка сохраняет контроль конфликтов версий, повторяющихся modId и зависимостей
необязательных компонентов.
