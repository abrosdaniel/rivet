# Большие наборы данных

Проверки списков, карточек и изменений задач.

Opt-in `CommunityLargeReadTest` создаёт в изолированной PostgreSQL 6000
документов и 96000 связей. Запуск: `RIVET_LARGE_READ=true
RIVET_LARGE_READ_OUTPUT=/tmp/large-read.json ./gradlew :core:postgresTest
--tests dev.abros.rivet.core.CommunityLargeReadTest --rerun` с переменными
подключения тестовой базы. Рабочую базу использовать нельзя: TestDatabase
очищает таблицы. Маркер: `RIVET_LARGE_READ_OK documents=6000 relations=96000 scenarios=8`.

Измеряются списки объединений, событий, объявлений и главной, с поиском
редкого названия и без него. Один предварительный запрос и пять измерений
на сценарий; JSON содержит медиану, максимум и контрольную сумму результатов.
Тест подтверждает повторяемость страницы, не задавая хрупких порогов времени.
Он измеряет SQL-списки, а не интерфейс, сеть или запись задач.

Списки отбирают документы и проверяют наличие связей до восстановления
коллекций участников/откликов/голосов. Материализованная выборка ограничена
11 документами; полное представление строится только для этой страницы.
Повторная сортировка сохраняет порядок и продолжение страницы при одинаковом
времени событий. Существующие индексы связей используются без миграции данных.

## Большие списки задач

`TaskLargeReadTest` включается через `RIVET_TASK_LOAD=true` и записывает
JSON по `RIVET_TASK_LOAD_OUTPUT`. Запускайте `:core:postgresTest --tests
dev.abros.rivet.core.TaskLargeReadTest --rerun` только на изолированной
тестовой базе: TestDatabase очищает таблицы. Набор: 6000 задач, объединение
с 1000 участниками, по 40 комментариев и 20 записей истории на задачу.
Шесть сценариев проверяют личный/групповой список со статусом open, поиск
по названию и коду. После предварительного запроса выполняются семь замеров.
Маркер завершения: `RIVET_TASK_LOAD_OK tasks=6000 members=1000 scenarios=6`.
Маркер `RIVET_TASK_PAYLOAD` сообщает размер полного и сокращённого JSON
одной тестовой задачи, до протокольного оформления и сетевого сжатия.

SQL материализует не более 21 задачи для страницы, затем исключает
комментарии, историю, склады, зависимости и резервы из данных списка.
Полные карточки продолжают читать сохранённые поля. Материализация
ограничивает стоимость преобразования JSON выбранной страницей;
фильтры, курсор, авторизация и правила выдачи кодов остаются прежними.

Поиск задач использует вычисляемые PostgreSQL-поля `task_search`,
`task_status` и `task_archived`. Они автоматически обновляются из `body`
при любой записи, включая прямые SQL-обновления; отдельного фонового
индексатора и риска отставания копии нет. Строка поиска сохраняет исходную
семантику: название, пробел, описание, пробел, код; регистр обрабатывается
PostgreSQL, `%` и `_` остаются буквальными символами.

Миграция 007 автоматически заполняет поля существующих записей при запуске
сервера. Исходные JSON, ревизии и коды не меняются. Поля занимают дополнительное
место для названия/описания/статуса; миграция обрабатывает существующую таблицу,
поэтому её время зависит от размера базы.

`TaskLargeReadTest` также сохраняет `<RIVET_TASK_LOAD_OUTPUT>.plans.json`
с `EXPLAIN (ANALYZE,BUFFERS,FORMAT JSON)` того же SQL и параметров. План
снимается отдельным подготовленным выражением: он может отличаться от
плана повторно используемого JDBC-запроса. Для пользовательской задержки
сравнивайте замеры полного `store.request`, а не только Execution Time.

## Полные карточки задач

Зависимости карточки читаются одним запросом вместе с кодами и краткими
полями. Выдача сохраняет порядок исходного списка, блокирующие записи
удалённых задач и ограничение владельцем/объединением. Пустой список
не обращается к БД. Диагностический таймер `task.dependencies.query`
использует общий opt-in механизм PerformanceMetrics. Если у задачи нет
ресурсных требований, общий складской запас не просматривается; сведения
о привязках самой задачи и резервах продолжают формироваться.

Opt-in `TaskDetailLoadTest`: `RIVET_TASK_DETAIL_LOAD=true`, путь отчёта
`RIVET_TASK_DETAIL_LOAD_OUTPUT`, задача `:core:postgresTest --tests
dev.abros.rivet.core.TaskDetailLoadTest --rerun`. Используйте только
изолированную тестовую базу с переменными подключения TestDatabase.
Набор: 11 задач с комментариями/историей и 704 складские привязки.
Шесть сценариев комбинируют 0/1/10 зависимостей и наличие ресурсов.
После предварительного запроса выполняются девять измерений полной
карточки с проверкой неизменности ответа. Маркер:
`RIVET_TASK_DETAIL_LOAD_OK tasks=11 stocks=704 scenarios=6`.

## Изменение цепочек и проверка прав задач

При изменении зависимостей каждый узел графа читается один раз за операцию.
Локальная таблица узлов не переживает запрос. Каждая корневая зависимость
сохраняет отдельный обход и прежний предел 200 узлов, включая проверку цикла
до повторного использования узла. Читаются только связи, владелец и группа.
Таймер `task.graph.query` доступен через опциональную подробную диагностику.

Права задач объединения проверяются по текущим статусу группы, владельцу
и роли конкретного игрока. Полный состав группы для этого не загружается;
права между запросами не кешируются. Закрытая группа, отключённые модули
и ограничения личных задач сохраняют прежние правила.

Opt-in `TaskGraphLoadTest`: `RIVET_TASK_GRAPH_LOAD=true`, путь результата
`RIVET_TASK_GRAPH_LOAD_OUTPUT`, запуск `:core:postgresTest --tests
dev.abros.rivet.core.TaskGraphLoadTest --rerun` на изолированной базе.
Сценарии: десять зависимостей с общей цепочкой из ста задач и проверка
прав в группе с 1000 участниками. Девять замеров после предварительного
запроса. Маркер: `RIVET_TASK_GRAPH_LOAD_OK nodes=110 members=1000 scenarios=2`.
