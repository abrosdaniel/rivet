# Семя Rivet

Семя — публичный GitHub-репозиторий, который описывает один Minecraft-сервер и его клиентскую сборку. Он содержит список модов и конфигов, требования к версиям, правила и новости. Игрок добавляет ссылку на репозиторий в Rivet и получает готовую сборку.

Этот шаблон включает пример `rivet.json`, клиентский конфиг и workflow публикации. GitHub Actions проверяет описание, вычисляет контрольные суммы и создаёт выпуск сборки. Отдельный сайт или сервис публикации не требуется.

## Как это работает

1. Описание и исходные файлы хранятся в репозитории.
2. Workflow проверяет компоненты и их источники, затем публикует манифест и файлы в GitHub Releases.
3. Rivet устанавливает выбранные компоненты и проверяет загруженные файлы по SHA-256.
4. Новая версия сборки выпускается изменением `version`; выбор необязательных компонентов сохраняется у игрока.

Версия сборки, версия Rivet и версия Minecraft — разные параметры. Rivet не устанавливает Minecraft и NeoForge: их выбирают в лаунчере по требованиям сборки.

<a id="setup"></a>

## Подготовка репозитория

Перенесите **всё содержимое** этой папки в корень публичного GitHub-репозитория, включая скрытую `.github`. После fork включите workflows во вкладке **Actions**, если GitHub попросит.

```text
rivet.json          Описание сервера и сборки
files/               Конфиги и другие файлы сборки
content/rules.md     Правила сервера
content/news/        Новости в Markdown
```

Workflow работает в вашем репозитории, используя инструменты Rivet. Релизы и файлы остаются у вас. Workflow и инструменты загружаются из ветки `main` репозитория Rivet. Каждый новый запуск использует актуальное состояние этой ветки; менять номер версии инструментов вручную не нужно.

<a id="project"></a>

## Описание сервера

Откройте `rivet.json` и заполните:

| Поле                      | Что указать                                                         |
| :------------------------ | :------------------------------------------------------------------ |
| `name`                    | Название в Rivet и списке серверов Minecraft.                      |
| `version`                 | Версия сборки, например `1.0.0`.                                    |
| `rivetVersion`           | Требование к версии Rivet, например `>=1.2.0 <2.0.0`.                            |
| `server.address`          | Домен или IP, при необходимости с портом: `play.example.org:25565`. |
| `minecraft.version`       | Версия Minecraft.                                                   |
| `minecraft.loaderVersion` | Точная версия NeoForge, требуемая клиенту.                       |
| `components`              | Моды и файлы для установки — примеры ниже.                          |

**Rivet:** версия мода — `A.B.C`: C исправляет ошибки, B добавляет совместимые функции, A обозначает несовместимые изменения. Совместимость подключения проверяется по протоколам и общим возможностям клиента и сервера; одинаковая A сама по себе не гарантирует работу.

| `rivetVersion` | Требование |
| :--- | :--- |
| `1.x` | Любой стабильный выпуск ветки 1 |
| `>=1.2.0 <2.0.0` | Минимум 1.2.0, исключая 2.0.0 и выше |
| `=1.2.0` | Только 1.2.0 |

Новые диапазоны и точные требования поддерживаются начиная с Rivet 1.1.0. Для клиентов 1.0.0 используйте старую запись. Диапазон пишется с пробелом между границами; нижняя граница включена, верхняя — нет. Предварительные версии в требованиях семени не поддерживаются.

Для существующих семян сохранён прежний смысл: `1.x.x` равно `1.x`; `1.0.x` задаёт минимум 1.0.0 в ветке 1; **`1.0.2` без знака `=` означает минимум 1.0.2 в ветке 1**, а не точный выпуск. В новых семенах используйте явные диапазоны или `=`.

Версия сборки `version` независима от версии Rivet. Повышайте её при изменении компонентов сборки. При переходе на другую основную версию Rivet обновите сервер, требование семени и версию сборки.

MOTD, иконка, онлайн и задержка приходят с Minecraft-сервера. Minecraft и NeoForge игрок устанавливает через любой лаунчер.

<a id="components"></a>

## Компоненты сборки

Каждый элемент `components` — мод или группа файлов. В шаблоне есть учебный конфиг: замените его своим компонентом и файлом либо удалите оба.

### Мод по ссылке

Добавьте в массив `components` такой объект, заменив название и ссылку:

```json
{
  "id": "example-mod",
  "name": "Название мода",
  "description": "Для чего он нужен игроку.",
  "kind": "optional",
  "files": [
    {
      "path": "mods/example-mod.jar",
      "urls": ["https://example.org/downloads/example-mod.jar"]
    }
  ]
}
```

Ссылка должна вести **непосредственно на файл** нужной версии, а не на страницу мода. Адрес из примера замените своим.

### Конфиг из репозитория

Положите файл в `files/your-mod-client.toml` и добавьте компонент:

```json
{
  "id": "client-config",
  "name": "Настройки сборки",
  "kind": "required",
  "files": [
    {
      "path": "config/your-mod-client.toml",
      "repositoryPath": "files/your-mod-client.toml",
      "policy": "preserve"
    }
  ]
}
```

`path` — место установки в игровой папке. `repositoryPath` — расположение исходного файла в вашем репозитории.

### Обязательность и зависимости

- `required` — обязательный компонент; используется, если `kind` пропущен. При переводе необязательного компонента в обязательный он включится при обновлении.
- `recommended` и `optional` — включены по умолчанию, но игрок может снять галочку. Его выбор сохраняется.
- `id` — постоянное уникальное имя из строчных латинских букв, цифр и дефисов.
- `dependencies: ["library-id"]` — компоненты, необходимые этому моду.
- `conflicts: ["other-id"]` — несовместимые компоненты.

### Запасные ссылки

В `urls` можно указать до **8 прямых HTTPS-ссылок** в порядке предпочтения. Rivet сначала проверяет кэш, затем пробует источники по очереди.

**Размер и SHA-256 вычисляются автоматически.** Все зеркала должны отдавать одинаковые байты: одинаковое название и версия мода на разных площадках этого не гарантируют. Недоступное зеркало вызывает предупреждение при публикации, несовпадение файлов — ошибку. Если недоступны все источники, выпуск не создаётся.

Для `repositoryPath` эталоном служит ваш файл; его копия в GitHub Release становится первым источником. При необходимости можно добавить `urls` с зеркалами той же копии.

### Обновление файлов

| `policy`   | Поведение                                                                             |
| :--------- | :------------------------------------------------------------------------------------ |
| `enforce`  | Привести файл к версии сборки. Обязательно для `mods/`.                               |
| `preserve` | Сохранить пользовательские изменения. По умолчанию для `config/` и `defaultconfigs/`. |
| `update`   | Обновить, если игрок не менял файл. По умолчанию для остальных разрешённых папок.     |

> [!IMPORTANT]
> Здесь только **клиентские файлы**. Не включайте миры, `options.txt`, `servers.dat`, пароли, `config/rivet-server.toml` и папку `rivet/`. Серверные моды и настройки устанавливаются отдельно.

## Правила и новости

- Правила — `content/rules.md`.
- Новости — отдельные `.md` в `content/news/`, например `2026-09-16-update.md`.

Замените учебные тексты своими. Ненужные файлы можно удалить.

<a id="publish"></a>

## Публикация

1. Сделайте commit и push в основную ветку.
2. Во вкладке **Actions** дождитесь успешного **Rivet project**.
3. В **Releases** появится `pack-v1.0.0` с манифестом и файлами.
4. Добавьте ссылку `https://github.com/ВАШ_АККАУНТ/ВАШ_РЕПОЗИТОРИЙ` в Rivet и проверьте установку.

Для изменения сборки повышайте `version`: `1.0.0` → `1.0.1`. Опубликованные номера не переиспользуйте. `rivet.lock.json` и `rivet.lock.sha256` создаются автоматически в релизе.

GitHub выдаёт токен публикации автоматически. Если правила репозитория ограничивают запись из Actions, разрешите workflow запись в **Contents** для создания релизов. Изменять основную ветку ему не требуется.

После сбоя повторите запуск во вкладке Actions или используйте **Run workflow** на основной ветке. Черновик дополняется, опубликованный релиз не перезаписывается. Rivet выбирает максимальную версию `pack-vA.B.C`; черновики и предварительные выпуски игнорируются. При недоступной сети используется проверенный кэш, при повреждении релиза показывается ошибка.

<a id="update"></a>

## Обновление сборки

| Изменение                                      | Что сделать                                                                  |
| :--------------------------------------------- | :--------------------------------------------------------------------------- |
| Название или адрес сервера                     | Изменить `name` / `server.address` и сделать push. Версию повышать не нужно. |
| Моды, конфиги, требования, новости или правила | Повысить `version` и сделать push.                                           |

Название и адрес проверяются при запуске игры, перед подключением и вручную; успешный результат кэшируется на минуту. Периодических запросов к GitHub нет. При недоступной сети используются последние проверенные данные.

## Диагностика публикации

Откройте упавший шаг в **Actions**. Проверьте прямые ссылки, совместимость модов с Minecraft/NeoForge и новую версию сборки. После устранения причины повторите запуск через **Re-run failed jobs** или отправьте исправления.

Неизвестный диапазон версий в JAR даёт предупреждение, явная несовместимость — ошибку. Публикация не запускает моды: проверьте сборку в игре.

<details>
<summary>Дополнительные параметры</summary>

- `sha256` у файла — необязательное закрепление конкретного содержимого. При несовпадении публикация остановится.
- `version` у файла — необязательна; по умолчанию используется версия сборки.
- `policies.customFiles` — `warn` по умолчанию или `deny`.
- `integrations.luckperms` и `theme` — дополнительные интеграции и оформление.
