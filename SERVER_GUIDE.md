## Установка

Rivet устанавливается в `mods/` сервера Minecraft 1.21.1 с NeoForge от 21.1.250 в ветке 21.1 и Java 21. Для серверных функций необходима PostgreSQL; клиентам нужен Rivet для меню и входа при включённом Auth.

При первом запуске создаётся `config/rivet-server.toml`. Запуск продолжится только после настройки подключения к базе. Параметры подключения применяются после полного перезапуска.

### PostgreSQL

Создайте базу `rivet`. Под администратором PostgreSQL подключитесь к ней через `psql` и выполните **один раз**:

```sql
CREATE ROLE rivet LOGIN NOSUPERUSER NOCREATEDB NOCREATEROLE NOREPLICATION;
\password rivet
GRANT CONNECT ON DATABASE rivet TO rivet;
CREATE SCHEMA rivet AUTHORIZATION rivet;
```

`\password` запросит новый пароль дважды. Отдельный пользователь ограничивает доступ мода его схемой.

В полном серверном конфиге заполните раздел:

```toml
[database]
host = "db.example.org"
port = 5432
database = "rivet"
username = "rivet"
password = 'ПАРОЛЬ_ПОЛЬЗОВАТЕЛЯ'
passwordEnv = ""
pool = 8
sslMode = "disable"
sslCert = ""
```

Пароль в TOML — **в кавычках**. Вместо `password` можно указать `passwordEnv = "RIVET_DB_PASSWORD"` и задать эту переменную процессу Minecraft. Если имя переменной заполнено, пароль берётся только из неё.

**Docker:** используйте Internal Host и порт Internal Port; контейнер Minecraft должен иметь доступ к сети базы. Публиковать порт БД в интернет не требуется. `sslMode = "disable"` подходит для доверенной внутренней сети; для внешнего подключения используйте `"verify-full"` и сертификат в `sslCert`.

> [!IMPORTANT]
> PostgreSQL нужна и при выключенном Auth. При ошибке подключения сервер остановит запуск с объяснением в консоли. Данные Rivet хранятся в БД отдельно от мира.

## Настройки сервера

Все настройки — в `config/rivet-server.toml`. [Полный шаблон с пояснениями](rivet/core/src/main/resources/rivet-server.toml). Имена параметров сохраняйте как в шаблоне; меняйте значения справа от `=`. Строки заключайте в кавычки, целые числа и `true`/`false` пишите без кавычек. `auth.mode = "false"` — строка, поэтому кавычки обязательны.

Разделы `[menu]` и `[community]` можно применить без перезапуска: откройте настройки сервера в администрировании, нажмите **«Проверить файл заново»**, просмотрите изменения и выберите **«Применить меню и разделы»**. Для остальных настроек нужен полный перезапуск сервера.

Обязательные разделы `[connection]`, `[auth]`, `[database]` сохраняйте со всеми параметрами. Пропущенные необязательные параметры получают значения из шаблона. При запуске недостающие настройки автоматически добавляются в файл вместе с пояснениями. Ваши значения и комментарии сохраняются; перед дополнением создаётся резервная копия `config/rivet-server-*.toml.bak`. Неизвестные параметры и неверные типы или диапазоны останавливают запуск; значения паролей в ошибках не выводятся.

| Раздел | Назначение |
| --- | --- |
| `[connection]` | Время ответа клиента при входе. |
| `[auth]` | Способ входа, регистрация и длина нового пароля. |
| `[database]` | Подключение к PostgreSQL. |
| `[statistics]` | Сбор и показ статистики игроков. |
| `[skins]` | Библиотека скинов, размер PNG и лимит сохранения. |
| `[votes]`, `[votes.actions]` | Голосования о наказаниях, допуск участников и разрешённые меры. |
| `[community]` | Состав меню, категории, типы и лимит объединений. |
| `[menu]` | Текст помощи и ссылки в «Помощи». |
| `[groups]`, `[board]`, `[events]`, `[polls]`, `[ideas]` | Доступность функций сообщества. |
| `[reports]` | Обращения и модерация Rivet. |
| `[server]` | Объявления, обслуживание и запланированная остановка. |
| `[tasks]` | Доступность задач и лимиты; `0` снимает лимит. |
| `[storage]` | Привязанные хранилища и подсчёт ресурсов задач. |
| `[retention]` | Сроки хранения обращений и корзины, предел журнала. |
| `[spark]` | Пороги нагрузки и частота предупреждений. |
| `[chat]` | Каналы, формат сообщений, цвета и координаты. |
| `[display]` | Оформление TAB и режим имён над головой. |
| `[updates]` | Уведомления об обновлениях Rivet в консоли. |
| `[pack]` | Раздача и обязательность клиентской сборки, папка подготовки. |
| `[pack.network]` | Адрес и TCP-порты раздачи. |
| `[pack.downloads]` | Скорость и число одновременных загрузок; `0` снимает ограничение. |

Допустимые значения и диапазоны указаны в комментариях конфига. Выключение поля статистики останавливает его сбор и скрывает его, но сохраняет историю.

### Отключение функций

В разделах `[groups]`, `[tasks]`, `[storage]`, `[board]`, `[events]`, `[polls]`,
`[ideas]`, `[reports]` и `[server]` параметр `enabled = false` выключает функцию
после полного перезапуска сервера. По умолчанию эти функции включены.

| Раздел | Что выключается |
| --- | --- |
| `[groups]` | Объединения, роли, приглашения и канал объединений; личные задачи остаются доступны. |
| `[tasks]` | Задачи, повторение задач и их показ в меню и HUD. |
| `[storage]` | Привязка сундуков к задачам, подсчёт запасов, резервирование и голограммы. Списки требуемых ресурсов в задачах остаются. |
| `[board]` | Доска объявлений. |
| `[events]` | События и напоминания о них. |
| `[polls]` | Голосования сообщества; голосования о нарушениях настраиваются отдельно в `[votes]`. |
| `[ideas]` | Предложения игроков. |
| `[reports]` | Обращения, жалобы и действия модерации через Rivet. Команды Minecraft и других модов сохраняют свои права. |
| `[server]` | Объявления, закрепление, техническое обслуживание и запланированная остановка сервера. Просмотр конфигурации и диагностика остаются доступны администрации. |

Хранилища требуют включённых задач. Чтобы выключить задачи, поставьте
`enabled = false` и в `[tasks]`, и в `[storage]`. Объединения для личных задач
не обязательны; при выключенных объединениях их задачи и запасы недоступны.

Выключение не удаляет записи. Фоновое обновление, напоминания и очистка корзины
отключённых функций не выполняются. После включения сохранённые записи снова
доступны. Очистка удалённых объединений откладывается, если задачи или хранилища
выключены: это сохраняет связанные записи. Старые ссылки не обходят выключатель сервера.

`community.sections` управляет составом меню. Выключатель функции действует
независимо от этого списка: добавление раздела в меню не включает его.
Новые параметры автоматически появляются в конфиге с пояснениями и резервной копией.

Чат и скины используют собственные `chat.enabled` и `skins.enabled`;
авторизация — `auth.mode`, голосования о нарушениях — `votes.enabled`.
TAB и имена над головой настраиваются независимо в `[display]`.
Интеграции с установленными поддерживаемыми модами подключаются автоматически.

### Примеры частых изменений

В существующем разделе `[tasks]` можно убрать все три лимита:

```toml
maxPerOwner = 0
maxSubtasks = 0
maxComments = 0
```

Положительное целое число задаёт предел, `0` означает отсутствие ограничения. Большие списки этапов и комментариев отображаются страницами; достижение лимита объясняется в интерфейсе. Повторяющиеся задачи учитывают тот же лимит владельца.

`maxPerOwner` учитывает все задачи, созданные игроком, включая задачи объединений и архив. Уменьшение лимита не удаляет записи и не запрещает их редактирование.

В `[chat]` значение `enabled = false` отключает обработку чата Rivet. `globalName = ""` скрывает название общего канала; `localName = "Рядом"` задаёт название локального. Синтаксис сообщений: `текст` — рядом, `!текст` — всем, `#Название: текст` — участникам объединения.

В `[spark]` стандартные пороги — TPS ниже 18 или MSPT выше 50 мс в течение 30 секунд; повторное предупреждение не чаще одного раза в 300 секунд. TPS — тики в секунду, MSPT — время одного тика. Этот раздел используется только при установленном серверном spark. Восстановление производительности сбрасывает отсчёт нагрузки. Предупреждения получают игроки с `rivet.diagnostics` через центр уведомлений Rivet; уведомление о готовом отчёте получает запросивший его администратор.

### Чат и TAB — независимые настройки

**Чат:** `[chat].enabled = true` включает чат Rivet, `false` оставляет обработку сообщений Minecraft или другому моду. Отдельных режимов `auto` или `compatible` у чата нет. Изменения применяются после перезапуска.

| Параметр `[chat]`                         | Назначение                                                             |
| ----------------------------------------- | ---------------------------------------------------------------------- |
| `local`                                   | Локальный канал; при выключении обычный текст отправляется в общий чат |
| `localRadius`                             | Радиус локального канала: 1–1000 блоков, в пределах одного измерения   |
| `group`                                   | Каналы объединений; участие проверяется сервером перед отправкой       |
| `localName`, `globalName`                 | Названия каналов; пустая строка скрывает метку                         |
| `localColor`, `globalColor`, `groupColor` | Цвет метки канала и индикатора над вводом; строка `"#RRGGBB"`          |
| `coordinates`                             | Разрешить кликабельные координаты `[pos]`                              |
| `format`                                  | Общий шаблон сообщения для всех каналов                                |
| `channelFormat`                           | Шаблон метки канала; целиком скрывается при пустом названии            |

История хранится в PostgreSQL между перезапусками. `history = 100` задаёт число
последних сообщений на канал и максимум сообщений, выдаваемых при входе (0–1000;
0 отключает запись и синхронизацию). Просроченные записи удаляются раз в минуту
порциями до 256 записей, даже при отключённом чате или записи истории.
`historyDays = 7` ограничивает срок хранения
(1–365 дней). Старые сообщения загружаются небольшими порциями. Общий канал
доступен всем, чат объединения — его текущим участникам, включая сообщения до
вступления. История локального канала доступна только тем, кто был получателем
сообщения при отправке. Отключённые каналы не синхронизируются; команды, личные
сообщения Minecraft и системные уведомления не записываются в эту историю.

Над строкой ввода показывается текущий канал: локальный с радиусом, общий или название объединения. Индикатор работает независимо от отключаемой справки чата и скрывается при вводе `/команды`. Цвета задаются в `[chat]`: `localColor = "#83C6C4"`, `globalColor = "#E2BE75"`, `groupColor = "#B9A3F2"`. Они применяются к метке канала, включая её скобки и разделитель, но не к тексту сообщения или LuckPerms. Если название общего канала пустое, цветной метки в сообщении нет; над вводом остаётся «Общий чат».

Если у локального сообщения нет других получателей в этом измерении и радиусе, автор один раз видит предупреждение с подсказкой использовать `!`. Оно повторится после появления получателей рядом и их последующего ухода либо после нового входа автора на сервер. Сообщение автоматически в общий чат не пересылается.

Канал объединения использует название объединения. Если координаты запрещены, `[pos]` остаётся текстом.

Координаты в чате отображаются как `[Обычный мир · X, Y, Z]` (также «Ад» и «Край»). При наведении виден автор точки; если измерение отличается, подсказка предупреждает об этом. HUD показывает `Другое измерение: Ад` и сохраняет цель до перехода в нужное измерение, достижения точки или ручной остановки. Для модовых измерений используется перевод `dimension.<namespace>.<path>`, если он есть, иначе идентификатор.

#### Формат сообщения

```toml
[chat]
format = "$channel$head$prefix$nickname$suffix: $message"
channelFormat = "[$channel] | "
```

В `format` переменная `$channel` вставляет готовую метку из `channelFormat`. В `channelFormat` она обозначает само название канала. Если название пустое, весь блок метки пропускается, включая скобки и разделитель.

`$head` — голова отправителя, если игрок включил её показ; `$prefix` и `$suffix` — оформление LuckPerms; `$nickname` — ник; `$message` — сообщение с сохранением кликабельных координат. Префикс добавляет пробел после себя, суффикс — перед собой только при наличии значения. Без LuckPerms оба значения пустые. Голова размещается строго на месте `$head`; переменную можно убрать.

Например, для вида `<Рядом | голова префикс ник суффикс>: сообщение`:

```toml
format = "<$channel$head$prefix$nickname$suffix>: $message"
channelFormat = "$channel | "
```

Оба шаблона — до 512 символов в одной строке. `$nickname` и `$message` обязательны; остальные переменные можно убрать. Каждую переменную можно использовать один раз, `$$` выводит буквальный знак доллара. Неизвестные переменные останавливают запуск с указанием поля. Текст сообщения и данные LuckPerms повторно как шаблон не разбираются. Новые поля дополняются в конфиге автоматически с резервной копией; изменения применяются после перезапуска сервера.

**TAB:** `[display].tab` определяет только список игроков:

- `auto` — оформление Rivet уступает известным клиентским модам оформления TAB;
- `rivet` — используется оформление Rivet;
- `compatible` — сохраняется стандартный TAB или оформление другого мода.

Режим передаётся клиентам сервером. Игрок может настроить внешний вид, но не переопределить серверный режим.

### Голосования о нарушениях

По умолчанию выключены. Инициатор выбирает игрока, причину, меру и срок бана/голосового мута **1–1440 минут**. Для мута нужен Plasmo Voice или Simple Voice Chat.

Голосовать может любой вошедший игрок, включая подключившихся после начала; цель голосования голосовать не может. Один игрок — один голос, выбор можно изменить до завершения. О начале голосования приходит уведомление; вошедшие позже получают его при подключении. Активное голосование доступно из уведомлений и выделено в разделе «Голосования».

Нужно не менее **2/3 голосов «за» среди проголосовавших** и одновременно **не менее половины числа допущенных игроков на старте** (без цели). Этот порог не меняется при входах и выходах. Длительность, минимальный онлайн, время игры инициатора и паузы задаются сервером.

OP, `rivet.admin` и игроки с `rivet.vote.protected` защищены от таких голосований. При установленном LuckPerms интеграция подключается автоматически. Пример:

```text
/lp group moderator permission set rivet.vote.protected true
```

## Регистрация и вход

| `[auth] mode` | Способ входа                                                  |
| ------------- | ------------------------------------------------------------- |
| `"false"`     | Auth выключен; действуют правила Minecraft.                   |
| `"base"`      | Пароль аккаунта на сервере.                                   |
| `"hybrid"`    | Пароль и возможность привязать официальный Minecraft-аккаунт. |

`registration` разрешает регистрацию; `minPasswordLength` задаёт минимум **нового** пароля: 6–128 символов, по умолчанию 6. Старые пароли продолжают работать.

`online-mode` в `server.properties` настраивается отдельно: для игроков без официального аккаунта нужен `false`; при `true` Minecraft сначала проверяет официальный аккаунт.

Вход проходит до загрузки мира. Смена пароля, привязка аккаунта и отзыв сохранённых устройств — в **«Безопасности аккаунта»**. Пароли хранятся как хеши Argon2id; при включённом Auth игровой TCP-трафик защищён TLS 1.3.

### Восстановление доступа

1. Убедитесь, что обращается владелец аккаунта.
2. Выполните в консоли `rivet auth reset PlayerName`.
3. Скопируйте код из ответа консоли и передайте владельцу лично. При сбросе из игры код видит только запросивший администратор — в окне с кнопкой копирования.
4. Игрок вводит код и новый пароль в форме восстановления.

Код одноразовый, действует **15 минут**; новый отменяет предыдущий. В PostgreSQL хранится только хеш и срок действия, автор выдачи — в журнале без кода. Файлы не создаются. Ответ консоли может сохраняться в её логах. Сброс отзывает устройства и сеансы, удаляет официальную привязку. В игре для сброса нужны вход через Auth и отдельное право `rivet.auth.reset`; OP и `rivet.admin` его не заменяют.

## Команды и права

Игрок указывается ником или серверным UUID; при неоднозначном имени нужен UUID.

| Команда                                                   | Действие                                                 |
| --------------------------------------------------------- | -------------------------------------------------------- |
| `/rivet`                                                  | Открыть меню.                                            |
| `/rivet help [раздел]`                                    | Справка по доступным командам.                           |
| `/rivet share <раздел> <id>`                              | Отправить доступную запись в чат.                        |
| `/rivet open <раздел> <id>`                               | Открыть запись; команда вызывается ссылкой в чате.       |
| `/rivet compatibility`                                    | Состояние серверных адаптеров и причины недоступности.   |
| `/rivet status`                                           | Состояние Rivet, БД, Auth и интеграций.                  |
| `/rivet player info <игрок>`                              | UUID, статус и статистика.                               |
| `/rivet reports`                                          | Последние пять обращений; ответы — в меню.               |
| `/rivet announce <текст>`                                 | Разовое объявление.                                      |
| `/rivet announce urgent <текст>`                          | Критическое предупреждение администрации.                |
| `/rivet announce pin <минуты> <текст>`                    | Закрепить сообщение на 1–10080 минут.                    |
| `/rivet announce unpin`                                   | Убрать закрепление.                                      |
| `/rivet maintenance on <минуты> <причина>`                | Ограничить новые входы на 0–1440 минут; `0` — бессрочно. |
| `/rivet maintenance off`                                  | Выключить обслуживание.                                  |
| `/rivet restart <секунды> <причина>`                      | Сохранить мир и остановить сервер через 1–86400 секунд.  |
| `/rivet restart cancel`                                   | Отменить запланированную остановку.                      |
| `/rivet auth reset <игрок>`                               | Выдать приглашение на восстановление.                    |
| `rivet auth reserve <игрок>`                              | Закрепить свободное имя; только консоль.                 |
| `rivet auth block <игрок>` / `rivet auth unblock <игрок>` | Заблокировать / разблокировать аккаунт; только консоль.  |

Обслуживание не отключает уже вошедших игроков, администраторы могут подключаться. **Повторный запуск после `/rivet restart` выполняет служба запуска или панель управления сервером** — включите автоматический перезапуск.

### Исправление статистики

Работает для существующих игроков в сети и вне сети. Изменения записываются в журнал.

```text
/rivet stats show Player
/rivet stats time set Player 120h30m
/rivet stats time add Player 5h
/rivet stats time subtract Player 30m
/rivet stats since set Player 2026-09-01
/rivet stats deaths set Player 12
```

Время — целые часы `h` и минуты `m`, итог неотрицательный. Дата — `YYYY-MM-DD` по времени сервера, не в будущем. Дата и время игры меняются независимо; текущая сессия учитывается, дальнейшая игра начисляется к новому итогу. Общее время влияет на допуск к голосованиям о наказаниях.

### LuckPerms

OP уровня 2 и `rivet.admin` дают административный доступ. Для отдельных функций выдавайте права при установленном LuckPerms:

| Право                                   | Доступ                                            |
| --------------------------------------- | ------------------------------------------------- |
| `rivet.stats.view` / `rivet.stats.edit` | Просмотр / изменение статистики командами.        |
| `rivet.announce`                        | Объявления и закрепление.                         |
| `rivet.maintenance` / `rivet.restart`   | Обслуживание / остановка.                         |
| `rivet.reports`                         | Обращения, ответы и закрытие.                     |
| `rivet.diagnostics`                     | Состояние Rivet и интеграций.                        |
| `rivet.pack`                            | Проверка и публикация клиентской сборки.           |
| `rivet.events`                          | Управление событиями.                             |
| `rivet.auth.reset`                      | Восстановление Auth; отдельное право даже для OP. |
| `rivet.vote.protected`                  | Защита от голосований о наказании.                |

Пример: `/lp group moderator permission set rivet.reports true`. Меню и команды проверяют права на сервере; `rivet.admin` также открывает журнал и экспорт.

## Необязательные интеграции

LuckPerms, Plasmo Voice, Simple Voice Chat, Waystones, Create: Access Denied и spark устанавливаются отдельно. Rivet обнаруживает их и подключает поддерживаемые возможности автоматически. Отдельных выключателей интеграций нет.

- **LuckPerms:** проверка прав, префиксы, суффиксы и основная группа с учётом текущего контекста игрока. Отсутствие API не выдаёт дополнительные права.
- **Plasmo Voice:** голосовая модерация и диагностика подключения; для управления правами требуется LuckPerms.
- **Simple Voice Chat:** голосовая модерация через голосования Rivet и диагностика подключения, микрофона и звука.
- **Waystones:** отдельный слой доступных игроку обычных камней на карте Rivet. Список выбирается на сервере через правила Waystones: активированные, глобальные и командные точки. Неактивированные скрытые камни не передаются. Нет телепортации, открытия точек или сохранения копий в личные метки. Адаптер работает автоматически при совместимом API и включённом модуле карты; без Waystones карта работает самостоятельно. Sharestones и Warp Plates не входят в этот слой.
- **Create: Access Denied:** совместимость списков доступа с идентичностью аккаунтов Rivet, без изменения UUID Minecraft.
- **spark:** панель производительности, профилирование, отчёты и предупреждения о нагрузке. Для просмотра требуется `rivet.diagnostics`; для действий — также права spark `spark.profiler`, `spark.healthreport` или `spark.all`. Rivet останавливает и отменяет только запись, запущенную из своей панели. Отчёты загружает сам spark в свой просмотрщик.

Состояние адаптеров доступно через `/rivet compatibility`; состояние клиентских интеграций — в технической сводке. Диагностика различает отсутствие мода, несовместимый API и временную ошибку. Три неожиданных сбоя отключают только соответствующий адаптер до перезапуска сервера или смены клиентского соединения.

Simple Voice Chat подключается через официальный API 2.5+ автоматически.
В диагностике голоса доступны подключение UDP, состояние микрофона и звука;
серверный мут Rivet отображается при подключении к серверу с адаптером.
Мут блокирует исходящий голос до его распределения в близкий, шёпотный или
групповой канал. Срок хранится по UUID в `rivet/voicechat-mutes.json` в папке
сервера и переживает переподключение и перезапуск. Включайте этот файл в
резервные копии. Просроченные записи не действуют и удаляются при следующей
записи. Аудиопакеты не обращаются к диску или БД. Собственные ограничения
других голосовых плагинов не снимаются.

Если установлены оба голосовых мода, для голосового голосования должны быть
доступны оба адаптера; наказание применяется к обоим. Существующий активный
мут не заменяется новым. Сбой одного API не считается успешным наказанием;
уже применённое ограничение другого адаптера автоматически не снимается.
Сам Simple Voice Chat и его сетевой порт настраиваются отдельно по
[документации мода](https://modrepo.de/minecraft/voicechat/wiki/server_setup).

Проверенные версии: LuckPerms NeoForge 5.4.150, Plasmo Voice 2.1.17, Simple Voice Chat NeoForge 1.21.1-2.6.22 (обнаружение API и серверный lifecycle), Waystones 21.1.46 с Balm 21.0.66, spark 1.10.124-neoforge-1.21.1, Create: Access Denied 0.0.4+c6.0.10.mc1.21.1 с Create 6.0.10. Наличие мода само по себе не гарантирует совместимость любой будущей версии его API.

История последних 30 отчётов spark сохраняется в папке мира `rivet/spark-reports.json`. Диагностика содержит графики за последние 15 минут. Предупреждения о нагрузке можно временно отключить для своего администратора до перезапуска сервера.

## Обновление и резервные копии

Перед обновлением сохраните PostgreSQL, `config/rivet-server.toml` и папку `rivet/`. Остановите сервер, замените JAR в `mods/` и запустите его. Миграции структуры БД выполняются автоматически. Не удаляйте `rivet/auth-identity.p12`: это идентичность сервера для Auth.

Версии Minecraft и NeoForge в опубликованной сервером сборке должны совпадать с установленными у клиента. Требования других модов проверяются отдельно.

База и пользователь PostgreSQL могут иметь любое имя: значения `database` и `username` должны соответствовать существующему подключению. Схема данных Rivet называется `rivet`.

### Требования версии Rivet

Клиент и сервер обмениваются сведениями до входа в мир. Основная версия Rivet
должна совпадать (`2.x` с `2.x`); версии сетевых протоколов сборки, Auth и меню
должны совпадать точно. Полный номер версии клиента должен быть не ниже
серверного: сервер 2.0.0 принимает клиент 2.0.0 или новее в ветке 2.x,
но не 1.x и не 3.x. Новые необязательные функции используются, если их поддерживают обе
стороны. Если сервер требует Auth или сборку, клиент должен поддерживать эти функции.
Ответ привязан к одноразовому запросу и ограничен `connection.handshakeTimeout`.

При обязательной сборке сервер сравнивает переданный клиентом `packHash` с хешем
опубликованного снимка. До подключения обычный клиент Rivet сверяет управляемые
файлы и предлагает необходимые изменения. Это проверка обычного клиента и сборки,
а не защита от подделанного клиента. Отдельный номер версии сборки не задаётся.
Без Rivet можно войти, только если сервер не требует Auth и обязательную сборку.

### Имена над головой

В `[display]` параметр `nameplates` задаёт режим имён над головой: `"rivet"` — оформление `префикс ник суффикс` через адаптер LuckPerms, `"base"` — обычные имена Minecraft, `"hidden"` — скрыть имена игроков. Значения пишутся в кавычках. Без LuckPerms режим `"rivet"` сохраняет обычные имена. Требуется перезапуск сервера; настройка независима от чата и TAB.

Режим `"hidden"` выполняется клиентом Rivet с поддержкой этой настройки. Клиенты без Rivet и старые клиенты не скрывают имена по этому параметру. Minecraft-команды scoreboard не изменяются. Для скрытия задайте `nameplates = "hidden"`.

Сохраняются стандартные правила Minecraft для скрытых имён, команд, приседания и строки scoreboard под именем. Если другой мод уже изменил или скрыл подпись, Rivet не заменяет её. Дополнительные сущности для подписей не создаются. Ник аккаунта и UUID не меняются; команды `/nickname` и `/realname` не добавляются.

## Клиентская сборка

Сервер публикует файлы из `rivet/pack/` и раздаёт их клиентам напрямую.
Для работы не нужен отдельный репозиторий сборки.

### Подготовка

1. Включите `pack.enabled` и настройте адрес и порт раздачи.
2. Подготовьте клиентские файлы и `rivet/pack/pack.toml`.
3. Перезапустите сервер и откройте TCP-порт раздачи.
4. Выполните `/rivet pack check`, затем `/rivet pack publish`.

### Настройки раздачи

```toml
[pack]
enabled = true
required = true
directory = "rivet/pack"

[pack.network]
bind = "0.0.0.0"
port = 25567
host = ""
publicPort = 25567

[pack.downloads]
totalMiB = 20
clientMiB = 5
concurrent = 4
```

Откройте TCP-порт 25567 и пробросьте его в контейнер. Minecraft продолжает использовать свой игровой порт. Пустой `host` означает адрес игрового сервера. `publicPort` задаёт внешний порт при отличающемся пробросе. Скорости указаны в МиБ/с, `concurrent` — одновременные передачи; `0` снимает соответствующее ограничение. Выключенный модуль не мешает работе остальных функций Rivet. Игроки, ранее
подтвердившие сборку, также могут подключаться после его отключения; установленные
файлы и сохранённый ключ остаются на клиенте. При повторном включении раздачи
ключ проверяется снова, а изменённый ключ требует подтверждения.

### Файлы и компоненты

```text
rivet/pack/
├── pack.toml
├── mods/
├── config/
├── defaultconfigs/
├── resourcepacks/
├── shaderpacks/
└── kubejs/
```

Поместите клиентские файлы в подпапки `mods`, `config`, `defaultconfigs`, `resourcepacks`, `shaderpacks` или `kubejs`. Minecraft, NeoForge и Rivet игрок устанавливает самостоятельно. В `pack.toml` задаются компоненты и правила конфигов:

```toml
[[components]]
id = "visuals"
name = "Оформление"
description = "Дополнительные ресурсы"
optional = true
selected = false
files = ["resourcepacks/visuals.zip"]

[[configs]]
path = "config/example.toml"
update = "replace"
```

`optional = false` делает весь компонент обязательным: игрок видит его название и описание, но не может снять галочку. `selected` управляет начальным выбором только необязательных компонентов; обязательные всегда включены.

Файлы вне компонентов обязательны. Конфиги по умолчанию устанавливаются только при отсутствии (`missing`); `replace` явно разрешает замену конкретного конфига. Личные существующие конфиги с правилом `missing` не становятся файлами сборки. Конфиги, установленные сборкой, сохраняются на клиенте отдельно для каждого сервера и восстанавливаются при возвращении; правило `replace` по-прежнему применяет опубликованный файл. Игрок управляет компонентами кнопкой «Сборка» в списке сетевой игры до подключения.

### Публикация

- `/rivet pack check` проверяет подготовленные файлы.
- `/rivet pack publish` публикует неизменяемый снимок для следующих подключений.
- `/rivet pack publish restart` активирует снимок при следующем запуске сервера.

Команды требуют `rivet.pack`. Редактирование или удаление файлов подготовки не изменяет текущую публикацию. Подключённые игроки не отключаются; начатые загрузки продолжают использовать свой снимок. Сервер автоматически создаёт TLS-ключ, который игрок подтверждает при первом подключении. Изменённый ключ требует нового подтверждения. Сохраняйте папку `rivet/pack-data/identity` при переносе сервера.

### Моды по ссылкам

Указывайте ссылку на **конкретную версию или файл**, а не страницу проекта:

```toml
# Имя переменной окружения сервера с ключом API CurseForge.
# Для Modrinth ключ не нужен.
curseforgeKeyEnv = "RIVET_CURSEFORGE_KEY"

[[mods]]
url = "https://modrinth.com/mod/ferrite-core/version/x7kQWVju"

[[mods]]
url = "https://www.curseforge.com/minecraft/mc-mods/example/files/1234567"
component = "visuals"

[[components]]
id = "visuals"
name = "Оформление"
optional = true
selected = false
files = []
```

Замените пример CurseForge ссылкой на нужный файл. `component` связывает мод с
компонентом; его обязательность задаётся через `optional`. Без `component` мод обязателен, но отображается отдельным файлом. В `files` компонента перечисляют
локальные файлы. Моды по ссылкам скачиваются при проверке или публикации в закрытый
кэш сервера; папка подготовки не изменяется. Клиент сначала скачивает мод по прямой
ссылке CDN Modrinth или CurseForge, сохранённой в публикации. Если источник недоступен
или файл не совпадает по размеру либо SHA-256, клиент скачивает проверенную копию
с сервера. Локальные файлы всегда загружаются с сервера. Отмена останавливает загрузку
без переключения на резервный источник. Клиент не обращается к API поставщика;
ключ CurseForge остаётся только на сервере.
Разрешение автора на распространение файлов нужно учитывать и для локальных JAR.
Если CurseForge запрещает распространение или не предоставляет загрузку через API,
проверка сообщает ошибку, не подменяя источник неофициальной ссылкой.

До публикации проверяются Minecraft, NeoForge, контрольная сумма, повторяющиеся
пути и идентификаторы модов, обязательные клиентские зависимости и диапазоны их
версий из метаданных JAR, включая вложенные JarJar-моды. Серверные зависимости
клиентской сборки не требуются. Отсутствующую библиотеку добавьте отдельной ссылкой
или локальным JAR. Зависимости не скачиваются автоматически с произвольно выбранной
версией. Зависимость должна быть обязательной либо находиться в том же компоненте,
что и использующий её мод: отключение компонента не должно ломать другие моды.

При удалении ссылки следующая публикация исключит её файл. Уже опубликованный
снимок продолжит работать до активации нового. Совпадение пути локального файла
и файла по ссылке считается ошибкой — оставьте один источник. Неизвестные параметры
`pack.toml` отклоняются. Новый параметр ключа добавляется с пояснением; исходный файл
сохраняется в закрытой папке `rivet/pack-data/settings-backups`.

## Карта

`[map] enabled = true` включает карту Rivet и навигацию. При `false` клиент
не исследует поверхность и не открывает карту, команды навигации отключены.
Изменение применяется после перезапуска. Личные данные карты сохраняются.
Идентификатор мира хранится в `rivet/map-world.json` внутри папки мира:
сохраняйте его при переносе мира; новый мир получает новый идентификатор.

`[map] radar = true` разрешает показ уже загруженных клиентом сущностей на карте
и миникарте. При `false` радар отключён независимо от настроек игрока.

`[map] caves = true` разрешает пещерные слои большой карты и миникарты.
При `false` Rivet отображает и исследует только поверхность; сохранённые пещерные
слои остаются на диске. Параметр применяется после перезапуска и автоматически
добавляется с пояснением в существующий конфигурационный файл.
Пещерная карта читает доступные клиенту чанки; запрет этой функции Rivet не заменяет
серверную защиту от получения блоков другими клиентскими модами.

### Позиции игроков на карте

`[map] positions = true` разрешает передачу живых позиций с учётом настроек
каждого игрока. Начальный выбор — вся карта, аудитория «Все игроки». Игрок может
выбрать ближайших игроков, участников своих объединений или скрыть позицию.
`nearbyRadius = 128` задаёт радиус режима «Только рядом» в блоках (1–4096).
Проверяется трёхмерное расстояние в одном измерении. Настройки сервера
применяются после перезапуска; новые поля добавляются при обновлении автоматически.

Позиции передаются отдельно от радара существ. Отключение
`positions` убирает серверные головы игроков с обеих карт. Скрытые, невидимые,
наблюдатели и не прошедшие авторизацию игроки не раскрываются этим источником.
Для аудитории объединений нужны действующее членство и включённый модуль;
права администратора не обходят выбор игрока. Координаты не записываются в БД.
